# v0.4.2.0 Release Log

## Release Scope

v0.4.2.0 is a release hardening pass for Deep Research implementation findings. The
scope is evidence discipline, release provenance verification, generated-docs freshness, public
proof-boundary honesty, checker gating, and structural witness hardening.

This release uses a minimal three-case local package-bound smoke gate. Raw current-release smoke
captures remain local diagnostic artifacts and are not committed or uploaded as GitHub Release
assets.

## Included Changes

- CI and the manual artifact workflow now check generated docs freshness.
- CI and the manual artifact workflow now check generated docs interactions.
- CI and the manual artifact workflow now run strict TTP operator contracts.
- CI and the manual artifact workflow now run field-operator architecture checks.
- The manual artifact workflow writes and verifies package provenance with package SHA, size,
  entry count, build-manifest SHA, and compiled-module-map SHA.
- `tools/check_release_provenance.py` verifies local package/provenance consistency without network
  access.
- `tools/check_live_default_witness_contract.py` now rejects common witness-marker theater without
  requiring canned exact model answers.
- Public generated docs were refreshed from `docs/index/**` sources and catalogue-derived data.
- docs/index visual/SSOT/design consolidation is complete: the Architecture carousel is
  selected-primary with scaled preview cards, Theory card-to-notation interaction is restored, and
  `docs/index/DESIGN.md` is the docs/index-scoped visual token/rationale source. This does not
  extend release proof beyond the local package-bound smoke gate.
- The canonical `T_lang: Ψᴺ ⇢ Ψᴵ` boundary is preserved as public output boundary language, not an
  uptake guarantee.
- The Deep Research implementation audit and next handoff were added under `docs/audits/`.
- Direct route/misuse fixtures were added for the fourteen under-fixtured modules from the
  operativity audit, with `tools/check_underfixtured_module_coverage.py` as a focused guard.
- A minimal three-case current-release smoke skeleton was added under
  `tests/smokes/current-release/v0.4.2.0/`; `CR-01` through `CR-03` are release-required local
  package-bound smokes, while `CR-04` through `CR-10` are deferred expanded-smoke slots.

## Verification Plan

The release gate runs source/build regeneration, generated docs freshness, package shape,
compiled runtime freshness, module boundaries, stubs, strict routing parity, IR integrity, strict
TTP contracts, docs interactions, field-operator architecture, render modes, recursive traversal,
register formalism bridge, smoke artifact structural checks, Python tool compilation, local package
build, and `git diff --check`.

The strict current-release smoke gate passed locally for `CR-01` through `CR-03` against the package
SHA recorded below. The strict smoke gate now invokes the live witness checker for manifest
`witness_required=true` cases, so witness-required PASS evidence needs package provenance,
`release-smoke witness capture mode`, and a valid witness contract. The release proves only that
bounded local package-smoke result, not broad live-output competence.
