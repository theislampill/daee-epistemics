# Topology capacity property suite

## Boundary

This suite is the bounded A15 deterministic core. It creates topic-neutral finite graph probes, independently extracts their produced dimensions, and checks structural conservation across ephemeral Stage01-Stage08 records. A pass is a structural property result for the generated probes. It is not semantic truth, arbitrary-input correctness, model behavior, package-faithful replay, release readiness, or proof of an upper bound.

The suite does not change the canonical Stage01-Stage08 runtime, shared handshake, state-capsule, witness, projection, preflight, CI, atomics, generated runtime, or package surfaces. Those integration edges remain explicit later deltas.

## Owners

- `schema/topology-capacity-spec.schema.json` defines the topic-neutral probe input. Cardinalities are probe data. The schema has no `maximum` or `maxItems` topology law.
- `tools/topology_capacity_lib.py` validates spec semantics, derives seed-stable identities, constructs dependency relations and parent-derived generation depth, emits explicit Stage03/04/05 re-entry-cycle data, and normalizes operation evidence independently of IDs and filler. It is pure standard-library logic and performs no filesystem, process, network, model, or orchestration work.
- `tools/generate_topology_capacity_cases.py` is the only record emitter. It retains the canonical semantic source spec, writes sidecars and exact public output before Stage08, then binds every artifact by raw SHA-256. The quarantined `taint` envelope is excluded from semantic source bytes. The generator writes only to a supplied absent directory; `--check-only` and `--self-test` retain nothing in the repository.
- `tools/check_topology_capacity_properties.py` derives expected identities, relations, cycles, parent depth, and event order through checker-owned logic from the retained source spec. It independently extracts actual dimensions and evaluates P1-P11-style conservation, lifecycle, dependency, projection, custody, and monotonic-closure properties. Producer `topology-dimensions.json` is evidence to verify, not the checker oracle.
- `tools/check_no_fixed_topology_floors.py` separates schema/acceptance law from telemetry and capacity canaries.
- `tools/check_case_registry_taint.py` is a shared A14/A15 boundary and remains read-only in this lane. Its self-test proves that changing or removing quarantined labels does not change expected topology, generated bytes, dimension signature, or verdict.

## Probe families

The committed probe set covers independent, chain, fan-out, fan-in, diamond, mixed, held activation, generated chain, generated fan-out, pre-emption, unknown-route HOLD, noetic-cycle/LoopBreak, and invalid event-DAG cycle relations. Baseline burden counts 1, 10, and 20 and submove counts 1, 3, 6, and 8 are capacity canaries. The 21-burden neighbor is required to prevent the 20-burden canary becoming a boundary.

Unknown route kinds remain visible under `HOLD` with a next action. A noetic dependency cycle remains present before an explicit LoopBreak and becomes acyclic afterward. The ordered event/provenance relation is separately required to remain acyclic.

Held baseline burdens record `hold -> hold-disposition -> activate -> Stage03 re-entry -> Stage04 execute -> land -> reread`. Generated children record `instantiate -> Stage03 re-entry -> Stage04 execute -> land -> reread`. The checker binds every ordered Stage03/04/05 cycle to the source-derived burden, origin, parent, parent-derived depth, route/re-entry/execution/hold/land events, obligation joins, reread, and exact cycle order. Generated fan-out parents remain anchored when an independent baseline burden is added.

The metamorphic command selects nine relations for every valid probe: alpha-renaming, independent-component permutation, conserved split, source-authorized merge, irrelevant context, payload-length variation, valid unknown-route HOLD, generated-child instantiation, and pre-empted resultant. Permutation applicability is derived from undirected components over pre-LoopBreak noetic edges plus generated-parent edges, never from a shape label. Whole applicable component blocks are reordered consistently while within-component parent/event order remains fixed. The committed probe set selects 108 rows, executes 98 positive siblings and 98 matched sabotages, and reports 10 stable `fewer-than-two-independent-components` rows as not applicable. The independent normalized oracle includes dependency graph, generation graph, parent, projection, event, lifecycle, and component relations. Generated-child preserves the base dependency shape and every pre-existing normalized relation. Five destructive join deletions remain separate pinned right-reason negatives.

The retained source spec partitions every pressure exactly once through canonical Plan03-axis decisions. Split/merge/shared-operation authority is source-bound and hashed before Stage03: it preserves ordered pressure-to-burden mapping and binds relation type, pressure, receiving burden, owner, operation, register, evidence identity, source frame, function, restoration vector, and the other Plan03 comparison axes. Stage02 retains the exact resolved decisions; Stage03 cites their IDs and hashes; every Stage04 ACT using a shared operation cites the exact Stage03 authorization. Orphan, duplicate, unused, substituted, locally self-authored, free-form, or stale-hash authority is rejected. Repeated normalized operation bodies receive zero additional credit without that chain.

## Deterministic commands

Run from the repository root:

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
python -m unittest tests/topology-capacity/test_topology_capacity.py -v
python tools/generate_topology_capacity_cases.py --self-test
python tools/generate_topology_capacity_cases.py --spec tests/topology-capacity/specs/valid/chain-b10-s3.json --check-only
python tools/check_topology_capacity_properties.py --self-test
python tools/check_topology_capacity_properties.py --probe-set tests/topology-capacity/probe-set.json --through-stage stage-04-burden-execution-act
python tools/check_topology_capacity_properties.py --probe-set tests/topology-capacity/probe-set.json --through-stage stage-05-mrp-reread-terminal-state
python tools/check_topology_capacity_properties.py --probe-set tests/topology-capacity/probe-set.json --through-stage stage-08-verifier-sidecars
python tools/check_topology_capacity_properties.py --metamorphic --probe-set tests/topology-capacity/probe-set.json
python tools/check_topology_capacity_properties.py --full-matrix
python tools/check_no_fixed_topology_floors.py --self-test
python tools/check_case_registry_taint.py --self-test
```

The canonical Stage05 negative is:

```powershell
python tools/check_topology_capacity_properties.py --explain-case tests/topology-capacity/specs/invalid/generated-child-missing-reread.json
```

It must exit `1` with earliest stage `05`, class `reread-terminal-coverage`, subcode `instantiated-burden-missing-reread`, downstream invalidation `06`/`07`/`08`, and no Stage06-08 or promotion artifact. Its executable same-stem expectation is `generated-child-missing-reread.expectation.json`.

`--full-matrix` is distinct from `--self-test`. It executes the deterministic product of burden canaries `1/10/20/21`, submove canaries `1/3/6/8`, and eleven valid dependency/lifecycle shapes: 176 cases. Its generated bytes, maximum case bytes, generation/validation time, and peak traced Python allocation are telemetry only, never acceptance floors or ceilings.

Stage07 binds `public_output_sha256` to exact bytes and those bytes must independently reconstruct from validated projection, operations, ordered public segments, and `T_lang`. A stale Stage07 hash fails before Stage08 custody; a self-rehashed truncated output still fails reconstruction. Stage08 structurally reconstructs the state capsule, field witness, and stage projection before checking the custody map, then binds `topology-spec.json`, `topology-dimensions.json`, Stage01-Stage07, all three sidecars, and exact `public-output.txt`. Rehashing a structurally altered sidecar cannot authorize it.

## Extension policy

Add a compact spec and stable seed when a new graph family or real implementation boundary is discovered. Do not add an expected answer, expected theological topology, citation list, conclusion, word/byte floor, or case-specific route. If a model smoke first reveals the defect, minimize the relation into neutral IDs and payloads, prove red-old/green-new behavior at the owning boundary, preserve a neighboring valid case, and add alpha-renaming, order, payload-length, irrelevant-context, and right-reason deletion pressure.

If a valid observed field exceeds a standing canary, replay its exact dimensions. A count beyond the matrix is not invalid. A resource failure must report a capacity/infrastructure boundary and preserve the topology; it must not silently prune nodes or become a universal semantic law.

## Deferred integration map

The following are intentionally not implemented in this bounded core:

- `tools/check_staged_runtime_handshake.py`: adapt generated records to the package-faithful Stage owners and register the A15 failure taxonomy/subcodes without duplicating property logic.
- `tools/gen_fixture_mutations.py`: resolve the A15 checker through the validation registry and enforce same-stem exact stage/class/subcode/downstream/forbidden-artifact expectations.
- `tools/daee_dry_run_emulator.py`: accept a generated topology spec/manifest and produce package-faithful Stage01-Stage08 artifacts.
- `tools/check_state_capsule.py`: join the generated lifecycle projection to the frozen v2 state owner without changing that schema in this lane.
- `tools/run_no_model_preflight.py`, `tools/run_local_ci.py`, and `tools/ci_registry.json`: wire the fast pairwise suite, classify the full deterministic matrix, and bind exact checker/spec/generator hashes.
- Witness/projection owners: adapt the bounded custom witness/projection records to `field-witness-envelope-v1` and `daee-stage-projection-v1`, preserving Stage06-08 parity and hash custody.
- Accepted A12/A13 and package surfaces: map generated artifacts through the independently accepted runtime-context/package-harness contracts in a later serialized integration lane. This bounded core still does not import, edit, or claim parity with those owners.
- Existing docs, atomics, and generated runtime: add pointers/non-claims only in their owning lanes, then rebuild generated surfaces from canonical owners.

Until those deltas land at one exact source state, this suite is not A15 terminal and cannot issue `NO_MODEL_CANDIDATE_MATURE`.
