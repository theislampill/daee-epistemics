# v0.3.1.0 — Render-Mode Governance Patch

**Date:** 2026-05-01
**Release:** daee-epistemics v0.3.1.0 — Render-Mode Governance Patch

> Superseded render-mode note: this file records the v0.3.1.0 release state. Current render-mode canon is in `README.md` §Render Modes: default visibly prints compact DSL/IR, `:dsl` remains concise DSL/IR, and `:audit` is deprecated as public output and retained only for internal/development compatibility.

---

## Summary

v0.3.1.0 is a targeted patch release on top of v0.3.0.0. It fixes a render-mode regression,
completes the compiled package with four runtime metadata files that were declared in
`RUNTIME_METADATA_COPIES` but absent from the v0.3.0.0 artifact, and repairs release-patch
formatting damage before push.

v0.3.0.0 introduced the compiled runtime architecture. v0.3.1.0 corrects three defects in that release:

1. **Render-mode regression.** The default `/daee-epistemics` invocation was emitting
   `## Diagnostic IR` code-fenced schema blocks, full `[Case State]` machinery, `Load Ledger`
   output, and `Render Permission Check` blocks — audit-mode behavior — in ordinary bounded prose
   responses. The Level 2 "Use when" rule also incorrectly allowed plain `/daee-epistemics`
   invocations with complex cases to trigger Level 2 lab-report render format.

2. **Incomplete package artifact.** The v0.3.0.0 `.skill.zip` was missing four files explicitly
   declared in `RUNTIME_METADATA_COPIES` in `tools/compiled_runtime_lib.py`.

3. **Encoding and version drift.** The release patch introduced UTF-8/Windows-1252 mojibake in
   canonical and generated runtime text. The source `contract_version` markers and generated runtime
   metadata also still identified the packaged reference surface as v0.3.0.0.

## Core Invariant Established

> **Historical v0.3.1.0 invariant:** governance runs in every mode; full procedural ledgers do not belong in default.

The recursive traversal (Diagnostic IR formation, all six gate checks, state/noetic re-read, held-route
rechecks, STOP / HOLD / RECURSE / PARTIAL decision) runs operationally in every mode. What differs
across modes is what is printed in the public response — not whether the traversal occurs.

**Discipline is universal; printout is mode-specific.**

## Render-Mode Corrected State

| Mode | Invocation | Render Shape |
|------|-----------|-------------|
| Default | `/daee-epistemics` | Compact DSL/IR header, bounded response, and state/noetic re-read; no raw Diagnostic IR, full Case State, `matched_modules`, route ledger, or load ledger |
| DSL | `/daee-epistemics:dsl` | Concise DSL/IR printout mode; compact Diagnostic IR / live-burden state when visible structure is requested |
| Audit | `/daee-epistemics:audit` | Deprecated as public output; retained only as internal/development compatibility for regression and procedural debugging |

### Default Mode — What Is Prohibited in Public Response

Regardless of case complexity, the default `/daee-epistemics` mode must not print:

- `## Diagnostic IR` code-fenced JSON block
- Full `[Case State]` block
- `Load Ledger` section
- `Render Permission Check` block
- Full procedural audit template
- The justification "case has multiple live burdens" as a trigger for Level 2 render

### Default Mode — Compact DSL/IR Surface

The following compact items are the intended default-mode visible compiler surface:

- compact read/confidence and claim/pattern/reason fields
- concealment, deformation, and DO-orient fields when active
- live noetic burden and current bounded operator
- held material and source-status/noetic-frame discipline
- decisive missing differentiator when required
- gate/release decision and state/noetic re-read

### Default Mode — Recursion Shape

Visible through compact DSL/IR and section progression, not printed gate machinery:

```
bounded move
→ state/noetic re-read: what cleared / what remains live / next licensed burden / decision
→ next bounded move (if eligible)
```

## Remaining Caveats

- Static checks do not prove live model behavioral equivalence.
- `runtime-grounding-v5` smoke artifacts passed the burden-completeness gate. Some fixtures are
  bounded-complete rather than hard-depth; each bounded PASS records first-order, second-order,
  and higher-order burdens handled, held burdens, and why no further pass was licensed.
- Default-vs-DSL-vs-audit render compliance depends on model behavior at runtime.
- Future source edits must happen in `atomics/skill/` and regenerate `skill/` via `tools/build_compiled_runtime.py`.
- Omnibus availability must not become activation; live inference must comply.
- Git operations must be performed from the host machine — the build sandbox cannot access `.git`.
