# v0.3.1.0 — Render-Mode Governance Patch

**Date:** 2026-04-28
**Release:** daee-epistemics v0.3.1.0 — Render-Mode Governance Patch

---

## Summary

v0.3.1.0 is a targeted patch release on top of v0.3.0.0. It fixes a render-mode regression and
completes the compiled package with four runtime metadata files that were declared in
`RUNTIME_METADATA_COPIES` but absent from the v0.3.0.0 artifact.

v0.3.0.0 introduced the compiled runtime architecture. v0.3.1.0 corrects two defects in that release:

1. **Render-mode regression.** The default `/daee-epistemics` invocation was emitting
   `## Diagnostic IR` code-fenced schema blocks, full `[Case State]` machinery, `Load Ledger`
   output, and `Render Permission Check` blocks — audit-mode behavior — in ordinary bounded prose
   responses. The Level 2 "Use when" rule also incorrectly allowed plain `/daee-epistemics`
   invocations with complex cases to trigger Level 2 lab-report render format.

2. **Incomplete package artifact.** The v0.3.0.0 `.skill.zip` was missing four files explicitly
   declared in `RUNTIME_METADATA_COPIES` in `tools/compiled_runtime_lib.py`.

---

## Core Invariant Established

> **Full recursion in every mode; full ledger only in audit.**

The grim-reaper traversal (Diagnostic IR formation, all six gate checks, State Refresh, held-route
rechecks, STOP / HOLD / RECURSE / PARTIAL decision) runs operationally in every mode. What differs
across modes is what is printed in the public response — not whether the traversal occurs.

**Discipline is universal; printout is mode-specific.**

## Render-Mode Corrected State

| Mode | Invocation | Render Shape |
|------|-----------|-------------|
| Default | `/daee-epistemics` | Prose-first; full grim-reaper traversal internal; compact Layer A items may be lightly surfaced; no full Diagnostic IR / Case State / Load Ledger / Render Permission Check in public response |
| DSL | `/daee-epistemics:dsl` | Compact formal Layer A / diagnostic-lab output; gating condition required (`:dsl` invocation or explicit request) |
| Audit | `/daee-epistemics:audit` | Full procedural ledger: runtime/bundle ledger, source-basis, routing gate, render permission, recursive passes, state refreshes, final governance |

### Default Mode — What Is Prohibited in Public Response

Regardless of case complexity, the default `/daee-epistemics` mode must not print:

- `## Diagnostic IR` code-fenced JSON block
- Full `[Case State]` block
- `Load Ledger` section
- `Render Permission Check` block
- Full grim-reaper procedural template
- The justification "case has multiple live burdens" as a trigger for Level 2 render

### Default Mode — Compact Layer A Light Surface (Permitted)

The following compact items may appear in a default-mode prose response:

- Discourse Orientation label (one line)
- Matched module IDs (inline, not a schema dump)
- Next eligible door and recursion decision (one line)
- Compact State Refresh statement
- Bounded move label

### Default Mode — Recursion Shape

Visible through section progression, not printed gate machinery:

```
bounded move
→ state refresh: what cleared / what remains live / next eligible door / decision
→ next bounded move (if eligible)
```

## Runtime Metadata Copies Added to Package

Four files declared in `RUNTIME_METADATA_COPIES` in `tools/compiled_runtime_lib.py` are now
present in the compiled package under `references/diagnostics/`. They are recorded in
`build-manifest.json` under `runtime_metadata_copies`. These are intentional runtime dependencies,
not source leakage.

| File | Purpose |
|------|---------|
| `module-catalogue.json` | Authoritative registry of all module `id`/`module_class` pairs. Required by `check_compiled_module_boundaries.py`. |
| `diagnostic-ir.schema.json` | JSON schema the Diagnostic IR must validate against before dispatch. |
| `operative-contract.schema.json` | JSON schema governing operative front-matter fields. |
| `operative-contracts.md` | Architecture specification for operative contracts. |

## Remaining Caveats

- Static checks do not prove live model behavioral equivalence.
- Default-vs-DSL-vs-audit render compliance depends on model behavior at runtime.
- Future source edits must happen in `atomics/skill/` and regenerate `skill/` via `tools/build_compiled_runtime.py`.
- Omnibus availability must not become activation; live inference must comply.
- Git operations must be performed from the host machine — the build sandbox cannot access `.git`.
