## Summary

v0.3.2.0 adds an additive Level 3 route-first execution path for Codex-capable
script runtimes. In Codex, `/daee-epistemics [input]` is documented to use
Level 3 by default when bundled scripts are available. Scriptless runtimes
visibly fall back to Level 1/2 behavior.

Level 3 performs deterministic routing given extracted features. Feature
extraction still includes span-backed interpretive components, and transformer
execution remains probabilistic. Pure-Hermes parity is not claimed, and
fixture-18-style capability limits remain honestly bounded.

The final v0.3.2.0 rebake hardens the repo/spec side against the observed
Level 1/2 thinning regression. It does not claim live-host behavioral recovery:
a manual Claude Level 1/2 rerun remains required before saying that regression
is behaviorally fixed.

The 2026-05-10 same-version asset refresh candidate adds generalized
pressure-dimension execution and real-smoke reporting boundaries. Local retained
real Codex CLI Level 3 hard moral-protest / worship-worthiness / source-worldview
canary evidence supports the installed Level 3 path on that canary; it is not committed, not packaged, and does not prove Claude
Level 1/2 scriptless behavioral recovery. GitHub Release asset replacement
remains pending until the intended asset is manually uploaded and verified.

## Post-Release Polish

After the initial v0.3.2.0 release, a small polish patch hardened the Level 3
closure matcher and release package hygiene:

- `check_execution.py` now accepts burden-structure labels such as `B3`,
  `Burden 3`, and `Third Burden` for the final required burden while still
  requiring matching `Land(BN)` and route-plan content.
- The Level 3 execution prompt now requires the literal checker format
  `Owner-floor: <owner-id>` before `Target:`, `Operation:`, and `Result:`.
- README and SKILL wording now share the same statement: Level 3 is the default
  path for `/daee-epistemics [input]` in Codex/script-capable runtimes when
  bundled scripts are available, and scriptless runtimes must visibly fall back
  to Level 1/2 behavior.
- `package.ps1` excludes Python cache files so local validation cannot pollute
  the release archive.
