# v0.3.2.0 Release Notes

**Date:** 2026-05-09
**State:** source-readiness commit, not a tagged GitHub Release.

v0.3.2.0 adds an additive Level 3 route-first execution path for
Codex-capable script runtimes.

## What Changed

- `/daee-epistemics [input]` is documented to use Level 3 by default in Codex
  when bundled scripts are available.
- Scriptless runtimes visibly fall back to Level 1/2 behavior.
- Level 3 extracts span-backed features, builds a deterministic route plan given
  those features, validates reconstruction and ontology licensing, generates an
  execution prompt, and checks post-output execution fidelity.
- Route plans now support `continuation_queue` so input-anchored downstream
  burdens can be released after `Land(B)` and `R(H,Delta)`.
- Fixture and stability tests were added for Level 3 routing, reconstruction,
  neighboring-TTP contrast, and repeated same-input stability.
- v15 owner adjudication resolved the proof denominator: support/index surfaces
  are not counted as operative owner gaps, and no release-blocking routing or
  loadform gap remained.
- The codon pilot was rejected/not needed; no owner packs or broad codon DSL
  were introduced.
- Nomenclature was normalized across noetic-state, aqidah-family, DSL/IR,
  Level 3, and TTP/owner/operator terms.
- Large smoke outputs, raw live transcripts, temporary owner lists, and
  developer live-run helper scripts were intentionally left out of the release
  commit.

## Honest Claim

daee-epistemics v0.3.2.0 includes additive Level 3 route-first execution for
Codex-capable script runtimes. Level 3 performs deterministic routing given
extracted features, validates route reconstruction, and checks post-output
execution fidelity.

Feature extraction still includes span-backed interpretive components.
Transformer execution remains probabilistic. Scriptless runtimes fall back to
Level 1/2 behavior.

## Non-Claims

- No deterministic feature extraction claim.
- No guaranteed long-output claim.
- No guaranteed all-runtime Level 3 claim.
- No pure-Hermes parity claim.
- No claim that fixture-18-style capability ceilings are solved.
- No claim that every TTP in the catalogue has full executable Level 3 rules
  beyond the implemented pilot/covered scope.
- No operative TST-specific routing logic.
- No codon pilot, broad codon DSL, or owner-pack rollout.

## Package Boundary

This is a source-readiness note. A package-bound release still requires an
explicit packaging pass, package hash recording, and current-package smoke
evidence. Binary skill archives are not committed to the repository.
