# docs/index source tree

`docs/index.html` is generated. Do not edit it directly.

Build command:

```powershell
python tools/build_docs_index.py
```

Freshness/interaction check:

```powershell
python tools/check_docs_index_interactions.py
```

## Source ownership

- `manifest.json` owns the tab registry, section order, and source map.
- `DESIGN.md` owns the docs/index visual identity. Its YAML front matter provides machine-readable colors, typography, spacing, radii, shadows, motion, stage-color, and component tokens; its Markdown body explains the design rationale. `tools/build_docs_index.py` emits CSS custom properties from it, and `tools/check_docs_index_interactions.py` checks the token boundary. Runtime meaning must stay in runtime architecture/atomics sources, not in the design file.
- `release-download.json` is generated static release metadata for the right-aligned `Download latest .skill` nav action. Refresh it with `python tools/update_release_download_metadata.py`; when GitHub lookup is unavailable, the tool writes a safe latest-release-page fallback instead of browser-side API calls.
- `sections/*.html` are bootstrap-preserved source fragments for the public wiki view. They are intentionally summarized and are not canonical runtime owners.
- `templates/index.html.tpl` owns the shell, CSS, and JavaScript surface.
- `templates/pipeline.html.tpl` owns the standalone generated `docs/daee-epistemics-pipeline.html` shell.
- The page masthead is a non-sticky generated shell surface. The tab navigation below it remains sticky while scrolling and includes the right-aligned download action outside the tablist.
- `sections/boundaries.html` owns the generated public `Boundaries` tab after Reference Library. It carries System Boundaries and Current Bridge Note as navigation/provenance context, not as runtime proof.
- Major docs/index surfaces declare `data-surface-role` values from `DESIGN.md`: `focal`, `support`, `control`, `provenance`, `raw-source`, `disclosure`, and `generated-snapshot`. Architecture, Owners/TTP, Theory, and Reference Library each keep one primary focal object; raw-source/provenance tables are collapsed or contextual unless the user is in an audit/source view.
- Architecture cards, paired Architecture pipelines, the copyable formal algebraic trace, and the Theory notation/source-owner metadata are generated from `docs/index/runtime-architecture.json`. The Architecture tab keeps two side-by-side color/phase-grouped vertical pipelines: a left plain/process reading and a right denser formal/runtime trace. Steps inside each color/phase group may flow horizontally with arrows, but the surface must not regress to long page-wide chip streams or scroll rows. The Theory tab keeps a related but distinct notation/glossary/context rendering of the same sequence, not a duplicate of either Architecture pipeline.
- Theory Deep Dive card-to-notation interaction is also source-backed by `docs/index/runtime-architecture.json`: `theory_cards`, `theory_card_notation_targets`, `mapping_rows`, and `notation_lines` generate the card controls, notation chips, active-state mapping, contextual Highlighted notation panel, and hidden source-owner metadata together.
- Exact daee-epistemics notation is preserved as source-owned meaning. Layouts must wrap, disclose, or resize around notation such as `𝓝`, `D₀`, `Ψᴺ`, `Ψᴵ`, `∇·T`, `∇×T`, `ⁿBᵢ[OPᵢ]`, `ΔⁿB{♥,ξ,Ω,σ,μ}/Δκ`, `LoopBreak(∇×T)`, `R(H, ΔⁿB{♥,ξ,Ω,σ,μ}, Δκ)`, `𝒞(Ψᴺ)`, `T_lang: Ψᴺ ⇢ Ψᴵ`, and `N_fiṭrī ∧ ʿaql ṣarīḥ`; do not simplify, transliterate, or ASCII-normalize it.
- The Architecture card carousel is presentation-owned by `templates/index.html.tpl` and generated by `tools/build_docs_index.py` from the same runtime architecture data. It must remain a user-controlled selected-primary carousel: one readable active stage, compressed identifiable side stages, previous/next buttons, arrow-key navigation, no automatic rotation, and print/no-JS access to all cards.
- `tools/check_docs_index_interactions.py` verifies all three runtime renderings stay aligned to the shared runtime architecture source while remaining non-identical renderings. The remaining Architecture interaction trace JavaScript is parity-checked against that same source by the checker.
- Final docs/index regression coverage includes the selected-primary carousel, scaled preview card structure, dense card-4 layout containment, Decision 2x2+COMPLETE layout, Theory card-to-notation activation, generated Reference Library snapshots, and large runtime/control JavaScript constant inventory.
- The Owner/TTP module table is derived from `atomics/skill/references/diagnostics/module-catalogue.json`; stale hand-authored module rows are not accepted.
- The Owner/TTP operator/family maps remain curated navigation data, but the default surface is a selected-detail workspace with source-derived counts. `tools/check_docs_index_interactions.py` checks source paths, catalogue-backed classes, family filters, owner tokens, matrix/source-table disclosure, and literal module-count claims against module-catalogue/frontmatter/source files.
- The Reference Library source-browser data and embedded source viewer snapshots are generated by `tools/build_docs_index.py` from `atomics/skill/README.md`, `atomics/skill/SKILL.md`, and `atomics/skill/references/**/*.md`. Its summary counts derive from `REFS`/`DOCS`, the selected preview is the default human path, and the full raw source map stays collapsed; stale hand-authored source snapshots or link tables are not accepted.
- Large JavaScript constants that contain runtime/control claims must be declared in `manifest.json` under `js_constants` and covered by a checker/source-basis entry. New large runtime/control constants without coverage fail `tools/check_docs_index_interactions.py`.
- `VISUAL_QA.md` defines the local browser visual pass for Architecture, Owners/TTP, Theory, Reference Library, and narrow/mobile behavior. Passing structural checks is not a visual pass.
- Framework, render, notation, and release/runtime claims must trace back to the listed owner files in `manifest.json`; these generated pages are public navigation surfaces, not runtime authorities. Release-download metadata powers navigation only: it is not runtime proof, smoke proof, or evidence beyond the documented package/provenance and bounded local smoke gate. Raw smoke captures remain local/ignored diagnostics and are not public site or release assets.

`manifest.json` classifies every tab and major visible block as owner-derived,
structured-source-derived, curated summary, static snapshot, or layout only.
Curated/static blocks are allowed for browser parity, but they must not be
treated as canonical proof when an owner file changes.

Bootstrap note: the initial source tree was mechanically extracted from the repaired `docs/index.html` to preserve browser parity before replacing stale hand-authored module data with owner-derived generated data.
