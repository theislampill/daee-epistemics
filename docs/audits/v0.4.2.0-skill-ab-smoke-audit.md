# SKILL.md A/B Smoke Audit

## Executive verdict

SKILL EXECUTION IMPROVED LOCALLY

The A/B/C failure was localized to the smoke invocation path, not to capture transport and not to
the generated runtime text itself. The previous runs asked spawned `codex exec` sessions to read
`skill/SKILL.md` while using a Windows read-only sandbox; logs show file-read attempts failed with
`CreateProcessWithLogonW failed: 1326`. The model then emitted smoke-shaped output without actually
loading the generated runtime.

Smoke D fixed the invocation by inlining the current generated `skill/SKILL.md` runtime into the
prompt while keeping the run read-only/no-mutation. Result: first-visible `field:` improved from
A=0/4, B=0/4, C=0/4 to D=4/4, and the new local validator passed Smoke D.

## Validator design

`tools/check_skill_ab_smoke_outputs.py` validates local `.daee/skill-ab-v0.4.2.0/smoke-*`
outputs without promoting them to release proof. By default it reports every phase but exits
nonzero only for the latest phase, so failing A/B/C baselines remain useful evidence after a
corrected D run.

It checks witness cases for first-visible `field:`, burden/witness surfaces, `R(H,Delta)` reread,
restorative response, and non-claim boundary. It checks ordinary non-witness output for
first-visible `field:`, a minimal governed-output signal, and obvious overclaim language. It also
reports suspected cause from logs, including read-only sandbox runtime-load failures. It does not
prove package-bound release smoke success, route correctness, or semantic truth.

## Hansei / 5 Whys for failures

Gap 1: first-visible `field:` banner was inconsistent in A/B/C and fixed in D.

Cause: A/B/C did not successfully load the generated runtime. The spawned read-only Codex runs were
asked to read `skill/SKILL.md`, but logs show Windows sandbox read failures. Smoke D inlined the
current generated runtime and produced first-visible `field:` in all four cases.

5 Whys:

1. Why did output miss first-visible `field:`? A/B/C outputs began with prose banner headings or
   `Layer A`.
2. Why did the contract not force it? The spawned run did not successfully read the generated runtime
   containing the contract.
3. Why did checks/smokes not catch it earlier? There was no local validator inspecting first line and
   runtime-load failure together.
4. Why did the model still produce smoke-shaped output? It followed the wrapper and prior context
   heuristically after the file-read failed.
5. Smallest countermeasure: inline the generated runtime for local smoke capture and add
   `tools/check_skill_ab_smoke_outputs.py`.

Gap 2: ordinary non-witness output was governance-thin in A/B/C and improved in D.

Cause: the ordinary case also suffered from the same runtime-load failure. Once the generated runtime
was inlined, D4 began with `field:` and contained minimal governed-output signals.

5 Whys:

1. Why thin? C4 rendered Layer A plus answer/closure but omitted the banner and burden/field spine.
2. Is ordinary output supposed to be compact? Yes, but compact should still be visibly governed.
3. What minimum should remain? First-visible banner and a compact governed-output signal.
4. Why did current wording not force that? The wording was not loaded by the spawned run.
5. Smallest countermeasure: validate ordinary-output minimum locally and run with the generated
   runtime actually present.

Countermeasure status: implemented and proven locally by Smoke D. Do not treat this as official
package/release smoke proof because the package artifact was not rebuilt or installed for host replay.
