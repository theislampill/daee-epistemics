## Gemba / Hoshin / Nemawashi / Muda-Mura-Muri / Kaizen integration

- Gemba: scoped to actual files, generated HTML, checker output, package artifacts, smoke captures,
  workflows, and UI state.
- Hoshin Kanri: scoped to major workstreams only, with objective/source/check/review named before
  release or architecture decisions.
- Nemawashi: required before source ownership, checker policy, release gate, package behavior,
  generated-doc architecture, or runtime entrypoint behavior changes.
- Muda / Mura / Muri: directs agents to reduce overloaded docs/UI/source maps/audit walls before
  adding panels, frameworks, or process.
- Kaizen: converts recurring regression classes into the smallest durable checker, runbook, source
  owner rule, token, or template rule.
- PDCA: scopes A/B or cleanup work to smallest safe changes with explicit plan, check, and act.
- Andon: stops dishonest pass claims and exposes failing check, owner, and next action.
- Hansei / 5 Whys: captures gap, cause, countermeasure, follow-up evidence, and systemic cause.
- Smoke Before Claim: requires command/result or evidence-type/risk before readiness claims.
- Plan Closure: requires every planned item to end as done, changed, blocked, deferred, or
  unverified.
