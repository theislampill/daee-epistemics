## Hard-Case Pressure-Dimension Hardening

The later golden-depth probe showed a broader failure class: a hard output can preserve the
route skeleton while leaving owner-floor execution too compressible. The fix is generalized,
not TST-specific.

- Level 3 route data now carries owner-local `pressure_dimensions` for covered owners such as
  FPD, M1, do-second-loop, V2, M8, P1, predication/attribute owners, grief/register holds,
  necessary-knowledge routing, and false-resemblance routing.
- `check_execution.py` treats those dimensions as burden-local quality gates for real
  non-simulated hard-case outputs. It rejects owner labels or Target/Operation/Result blocks
  that do not pressure the actual premise, criterion, warrant, source-frame, predicate,
  register, or restoration vector.
- Source-operative dimensions require burden-local direct quotation when the route carries a
  source-request feature. This is not an arbitrary source-count gate.
- The old retained real TST output now fails the stronger checker against a regenerated route
  because it lacks burden-local operative quotations for source-requested do-second-loop and
  P1 work and has a weak input-anchor pressure window in V2.
- Level 2/scriptless governance was also strengthened: `pressure_dimensions` is an implementation
  analogue, not a public field. Default output must execute the owner-specific pressure in prose
  without printing raw route data or becoming a Level 3 ledger.
- Non-TST checker samples were added for predication/category-pressure output that merely says
  pressure dimensions were satisfied. This avoids overfitting the guard to the TST probe.

Remaining gate: the TST probe is only a specimen of the broader hard-case failure class.
Mechanical pass plus qualitative inspection can support source readiness, but release claims
still require a fresh intended-runtime behavioral smoke and the separate manual Claude Level 1/2
scriptless rerun.
