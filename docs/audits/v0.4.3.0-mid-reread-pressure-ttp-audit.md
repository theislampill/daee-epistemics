# v0.4.3.0 Mid-Reread Pressure TTP Audit

## Executive verdict

MID-REREAD PRESSURE TTP IMPLEMENTED

## Goal

State reread `R(H,Δ)` existed, but without a specific reread-time pressure harness it could become
cosmetic: a named refresh that did not constrain STOP, HOLD, RECURSE, LoopBreak, or closure.

`TTP-MRP-mid-reread-pressure` makes `R(H,Δ)` operational by requiring the post-landed reread state
to activate matched pressure TTPs/operator classes before routing is licensed.

## TTP contract

Class: reread-time orchestration TTP / activation harness.

Trigger:

- `Land(ⁿB)` or partial `Land(ⁿB)` has been recorded.
- `R(H,Δ)` is deciding STOP / HOLD / RECURSE / PARTIAL / LoopBreak / closure.
- A new burden, recoil, churn, or closure graph movement appears during post-landed reread.

Inputs:

- current burden `ⁿB`;
- landed burden delta `ΔⁿB` and `Δκ`;
- held set `H`;
- dependency graph and terminal-state accounting;
- active `∇·T` and `∇×T` diagnostics;
- optional `field_witness` evidence;
- `T_lang` non-guaranteed-uptake boundary.

Pressure activation slots:

- freeze-landed-move;
- dependency-tug;
- hidden-framework-recoil;
- entailment-pressure;
- doubt-churn-guard;
- reorientation-reminder.

Each slot must name an activated TTP/operator, a pressure class, or an explicit TTP coverage gap.
MRP does not duplicate those owners. It records what their outputs license.

Route outputs:

- stable reread -> closure witness / STOP for the scoped pass;
- genuine new dependency -> RECURSE plus graph edge;
- partial but real burden -> HOLD;
- churn / label-pressure / unlicensed recoil -> LoopBreak(`∇×T`) or STOP;
- reorientation/reminder -> closure or HOLD without proof-stacking.

Non-claims:

- MRP does not claim guaranteed uptake.
- MRP does not claim psychological acceptance.
- `T_lang: Ψᴺ ⇢ Ψᴵ` remains language-mediated coupling, not soul access or control of guidance.

## Runtime behavior

MRP turns state reread from cosmetic refresh into licensed burden economics: fewer fake burdens,
more real burdens, and no unlicensed closure.

MRP is not an output-shortening mechanism. It blocks unlicensed expansion, and it requires licensed
expansion when `Land(ⁿB)` exposes a genuine downstream burden or structurally licensed pre-voiced
recoil.

MRP gives `∇·T` and `∇×T` active work inside `R(H,Δ)`:

- neutral/settled `∇·T` plus null/resolved `∇×T` may license stable closure;
- non-neutral `∇·T` with real downstream burden requires HOLD or RECURSE;
- non-null `∇×T` from churn or label-pressure requires LoopBreak or STOP;
- hidden-framework recoil must be marked framework-concession-bound or dispatched to existing owners
  if the burden is real;
- non-neutral `∇·T` plus non-null `∇×T` cannot license simple closure without explanation.

## Checker behavior

`tools/check_mid_reread_pressure.py` fails when MRP is decorative:

- pressure slots lack activated TTP/operator, pressure class, or coverage gap;
- `R(H,Δ)` is invoked without observable reread consequence;
- closure is claimed while `∇·T` is non-neutral without HOLD/RECURSE explanation;
- closure is claimed while `∇×T` is non-null without LoopBreak, STOP, HOLD, or graph-bound recursion;
- graph deltas omit terminal-state accounting;
- RECURSE lacks graph delta;
- hidden-framework recoil is treated as an unqualified landed burden;
- doubt-churn leads to proof-stacking;
- `T_lang` claims guaranteed uptake.

The checker includes contraction, expansion, pre-emption, and hold cases so MRP cannot always stop
or always expand.

## Reconstructibility link

MRP connects route licensing to visible closure witness graph and optional `field_witness` evidence:

- MRP licenses whether a new graph edge exists after reread;
- MRP prevents false closure where downstream burdens remain;
- MRP prevents infinite proof-stacking where `LoopBreak(∇×T)` should occur;
- MRP records active `∇·T` / `∇×T` effects and the TTP/operators/classes that pressured them;
- MRP preserves the `T_lang` non-guaranteed-uptake boundary.
