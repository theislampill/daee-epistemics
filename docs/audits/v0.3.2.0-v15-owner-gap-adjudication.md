# v0.3.2.0 v15 Owner Gap Adjudication

## Purpose

Adjudicate the 34 strict PARTIAL owner proof gaps left by v14 before considering any codon or Level-2 forcing pilot.

Evidence boundary: diagnostic working-tree proof evidence only. This is not package-bound release smoke evidence.

## Starting Point

v14 left 34 strict PARTIAL proof gaps. The dominant v14 failure reasons were:

- target owner was marked held rather than executed
- expected owner-floor tokens were not visible enough
- owner floor was not rendered as operative B.s work
- session-only no-usable-output artifacts

Subagent and local audit found no missing atomics file, generated bundle, compiled-module-map path, or owner-loadform path for the 34 owners.

## Stage 1 Patches

Concrete defects found and patched:

- Harness false negative: `owner_held_marker()` treated nearby downstream `held` language as proof that the target owner itself was held. It now lets output-visible owner-floor B.s work pass when downstream holds are separate.
- Harness no-output detection: session-only proof output is now `FAIL` / no usable proof output instead of token invisibility.
- Proof-queue defect: complex proof prompts made the hidden authority criterion first-live and correctly caused target-owner HOLD. The 34 complex prompts now make the target owner first-live and hold authority/downstream material unless independently triggered.
- Proof-oracle defect: the 34 `expected-owner-floor.md` records now use owner-specific proof anchors rather than truncated/generic fragments.
- Token oracle defect: generic words such as `state`, `position`, `objection`, `criterion`, `standard`, `unless`, and `downstream` are filtered from expected-floor matching.

No owner bodies were patched. No atomics/runtime rebuild was needed for Stage 1.
