# v0.3.2.0 Level 3 Shortfall Diagnosis

## Purpose

This report records the pre-patch diagnosis for the Level 3 shortfall campaign.
It starts from the prior release-hardening result: Level 3 routing, reconstruction,
and execution checking worked, but the TST / Richard-Lael hard smoke did not
substantively exceed the Sonnet golden behavioral standard. The failure was not
length alone. The TST output landed the first-live FPD + M1 burden and then
honestly held/deferred downstream work instead of traversing the broader
input-anchored burden chain.

## Architectural Conclusion

The shortfall is primarily architectural in the Level 3 route-plan carrier, not
a missing owner-pack or codon problem. The route plan needs a bounded continuation
primitive:

- `first_live_burden`
- `continuation_queue`
- release conditions tied to `Land(B)` and `R(H,Delta)`
- `reread_required`
- `closure_gate`

This does not create a second DSL or new TTP taxonomy. It makes existing
output-release and recursive-state-transition semantics executable inside
Level 3. Every queued burden or submove must be input-span anchored; otherwise
it is framework dumping and must be rejected.

## Generality Audit

The TST/Richard-Lael case is the regression fixture, not the architecture.

General elements:

- New features are noetic/discursive pressure classes:
  `feature.accountability_compression`,
  `feature.coercive_guidance_demand`,
  `feature.opponent_worldview_frame`,
  `feature.mercy_worthiness_protest`, and
  `feature.source_substantiation_request`.
- `continuation_queue` is generated from route-plan structure: span-backed
  lower-priority, blocked, or yielded candidates become queued only when the
  first-live blocker lands and no hard hold blocker is first-live.
- `check_execution.py` rejects shallow first-burden-only output for any route
  plan with a non-empty continuation queue.
- `execution_prompt.md` is generated from the route plan and queue entries; it
  does not contain case-name knowledge.
- Grief-coded cases remain true HOLD cases and receive no queue, proving the
  continuation primitive is not blindly forced.

Fixture-specific elements:

- The regression fixture name and its concrete spans are TST-specific because
  they test the hard smoke that exposed the bug.
- The executable scripts and data do not contain TST/Richard/Satanist-specific
  branches. A residue scan found those strings only in the regression fixture
  input. The routed feature is the general `feature.opponent_worldview_frame`,
  backed by explicit source-worldview/opponent-frame spans.

This is therefore a genus-level continuation primitive: it handles imported
tribunal / moral protest / hiddenness-punishment / source-worldview cases by
span-backed queueing, while preserving non-release for register holds and other
hard blockers.

## Release-Language Guard

The campaign must keep architecture and execution-model capability separate:

- If the fixed route plan and execution prompt produce Sonnet output that meets
  or exceeds the golden while Hermes remains partial, classify the architecture
  as sound and Hermes as execution-capability-bound.
- If Sonnet on the same route plan still falls short, the route/prompt still
  under-specifies warranted traversal.
- Do not claim pure-Hermes parity, do not claim fixture-18 capability is fixed,
  and do not treat padding as improvement.

## Final Patch Result

The final Level 3 pass implemented the continuation primitive in the generated
route plan:

- `first_live_burden`
- `continuation_queue`
- span-backed queue entries
- owner-floor `land_requirements`
- queue `release_conditions`
- per-burden `reread_required`
- `closure_gate`

The final TST smoke at
`smokes/level3-v0.3.2.0-final-gate/02-tst-richard-lael-lillard/` produced:

- 22,512 characters
- five visible burdens
- 15 owner-floor emissions
- five `Land(B)` emissions
- five `R(H,Delta)` emissions
- first-live owners: `foreign-premise-detection`, `M1-self-refutation`
- continuation queue: `do-second-loop`, `V2-reconstituting-reason`,
  `M8-reductio`, `P1-fitrah-restoration`
- reconstruction: pass
- validation: pass
- execution check: pass

The same shared primitive also affected the imported-tribunal smoke, while the
grief-coded objection remained a governed HOLD with no forced queue. This closes
the specific architecture gap found in the shortfall diagnosis: Level 3 no
longer treats first-live FPD/M1 as exhausting a complex input when downstream
burdens are span-backed and licensed after `Land(B)`.

## Architecture + TTP Alignment Audit

- Big-picture thesis alignment: PASS. The patch strengthens the intended chain:
  surface discourse -> typed noetic state / DSL-IR -> meta-noetic memetic
  feature detection -> constrained owner routing -> owner-floor execution ->
  burden sequencing -> `B.s` -> `Land(B)` -> `R(H,Delta)` -> state re-read.
- TTP owner-governance alignment: PASS. Queued owners are existing owners with
  owner-file support: FPD/M1 for imported tribunal and criterion test,
  `do-second-loop` for hujjah/accountability and coercive-guidance correction,
  `V2` for reason/evidence repair, `M8` for consequence trace, and `P1` for
  bounded restoration after upstream burdens land.
- Generality of new features: PASS. New features are genus-level
  noetic/discursive signals: accountability compression, coercive guidance
  demand, opponent worldview frame, mercy/worship-worthiness protest, and source
  substantiation request.
- Fixture-specific residue remaining: only the regression fixture text and
  expected-file name are TST-specific. Scripts and route data do not branch on
  TST/Richard/Satanist strings.
- Continuation queue: genus-level, not TST-shaped. It queues span-backed
  blocked/yielded owners only after a first-live blocker lands and never when
  hard HOLD blockers such as grief/register owners are first-live.
- Owner-file faithfulness: PASS. Each selected or queued owner has an
  owner-floor basis in the corresponding owner file and a `land_requires` entry
  in the trigger matrix.
- Under-call / over-call status: the earlier under-call of downstream TTPs is
  fixed for imported-tribunal/worldview-frame cases. The grief-coded HOLD smoke
  demonstrates no broad over-call of continuation.
- Governance effect: strengthened generally. The checker now rejects shallow
  first-burden-only output whenever a route plan contains a licensed
  continuation queue, while still allowing legitimate HOLD when no queue is
  licensed.
- Release claim: narrow. Level 3 can claim deterministic routing given
  extracted features, span-backed continuation queues, reconstruction/validation,
  and execution checking. It should not claim deterministic feature extraction,
  pure-Hermes parity, or guaranteed transformer execution on all highest-depth
  cases.
