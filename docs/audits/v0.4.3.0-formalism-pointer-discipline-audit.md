# v0.4.3.0 Formalism Pointer Discipline Audit

## Executive verdict

FORMALISM POINTERS CLEAN

The formal notation is already serving as a source-ownership and design-boundary map. The audit
found no P0 source-owner drift and no need to redefine symbols, simplify notation, or add
SOLID/GRASP/CUPID/ACID/BASE rhetoric to runtime output. The high-leverage patch is governance-only:
`AGENTS.md` now states that these principles are audit pointer discipline, not runtime prose.

The primary risk is future misuse, not current drift: a maintainer could treat a symbol as
decorative math, flatten `Ψᴺ` / `Ψᴵ`, or let docs/index become the source of truth. Existing owners
and controllers already block the important misuse classes.

## Cross-principle findings

### SOLID

- Single Responsibility: the major operators have one clear job. `∇` ranks eligible route
  pressure; it does not prove truth. `∇·T` and `∇×T` diagnose post-`Δ` field state; `LoopBreak`
  performs only licensed repair.
- Open / Closed: new TTPs and child modes extend through module owners, catalogue entries, and
  `ⁿBᵢ[OPᵢ]` without redefining `ⁿB`, `R(H,Δ)`, or `𝒞(Ψᴺ)`.
- Substitutability: different owner modules can operate under the same burden/submove contract if
  they preserve target -> operation -> result -> `Land(ⁿB)` -> `R(H,Δ)`.
- Interface Segregation: runtime interfaces are small enough. `T_lang` remains public coupling
  only, not closure, truth, uptake, and guidance all at once.
- Dependency Inversion: `SKILL.md` depends on Diagnostic IR, recursive-state, render, output, and
  owner contracts rather than hard-coded case examples wherever v0.4.3.0 cleanup proved this safe.

### GRASP

- Information Expert: `diagnostic-ir.md` knows IR/register bridge truth; `recursive-state-
  transitions.md` knows reread, held state, recursion, and field operators; render/output owners
  know visibility and witness floors.
- Creator: `tools/build_compiled_runtime.py` creates generated `skill/**`; `tools/build_docs_index.py`
  creates docs/index generated surfaces. Generated files are artifacts, not source.
- Controller: `check_field_operator_architecture.py`, `check_ir_instance_integrity.py`,
  `check_ttp_operator_contracts.py`, `check_spec_authoring_pack.py`, and
  `check_skill_ab_smoke_outputs.py` control validation.
- High Cohesion: symbol meaning, render visibility, and output release are mostly separated by
  owner. The formalism doc is a theory/spec projection, not a replacement owner.
- Low Coupling: docs/index/runtime-architecture.json points to runtime owners instead of owning
  runtime semantics. This is the right coupling shape.
- Protected Variations: likely changes are protected by schema-light boundaries, field-operator
  forbidden-pattern checks, generated-runtime freshness, and smoke notation guards.

### CUPID

- Composable: operators compose through the spine `IR -> ∇ -> ⁿB -> ⁿBᵢ[OPᵢ] -> Land -> Δ ->
  diagnostics -> R -> closure`.
- Unix philosophy: each operator does one thing well. `∇×T` diagnoses circular dependency;
  `LoopBreak(∇×T)` resolves only when owner-licensed.
- Predictable: the same meanings appear across formalism doc, runtime owners, docs/index source,
  checkers, and smoke validator.
- Idiomatic: notation is repo-native control grammar, not decorative generic math.
- Domain-based: `N_fiṭrī ∧ ʿaql ṣarīḥ`, `Ψᴺ`, `Ψᴵ`, and register symbols serve the daee-epistemics
  diagnostic/restorative domain rather than importing generic software vocabulary into runtime.

### ACID

- Atomicity: symbol-owner patches can be made in atomics/docs owners and rebuilt; generated
  runtime/docs are rebuildable artifacts.
- Consistency: atomics source, generated runtime, docs/index source projection, and checkers agree
  on the main operator boundaries.
- Isolation: docs/index visual work is isolated from runtime semantics because
  `runtime-architecture.json` is a source projection and generated HTML is not edited directly.
- Durability: invariants are backed by static checks, compiled-runtime freshness, docs/index
  freshness/interactions, and v0.4.3.0 Smoke E/F validator.

### BASE

- Basically Available: local diagnostic surfaces such as docs previews and local smoke outputs can
  exist for inspection without becoming release proof.
- Soft state: `.daee` smoke outputs and docs previews are diagnostic, not canonical runtime source.
- Eventual consistency: generated docs/runtime are rebuilt from owners and checked before claims.
- Boundary: BASE does not apply to package/release proof. Release gates remain strict and
  package-bound.

## Andon / Hansei / 5 Whys

Andon event: initial Smoke H validation failed on H6 with `possible overclaim language:
guaranteed uptake`.

Status: validator failed; live output preserved the non-claim boundary.

Owner: `tools/check_skill_ab_smoke_outputs.py`.

Next action taken: revise the overclaim detector so nearby negation is recognized without weakening
the formalism token guard.

Hansei:

- Gap: the validator treated a negated uptake phrase as an overclaim.
- Cause: the previous check looked for a small allowlist of exact negated phrases and missed
  conjunctions such as "not access to the soul or guaranteed uptake."
- Countermeasure: add `has_unnegated_phrase(...)` with a local negation window before failing
  overclaim phrases.
- Follow-up evidence: root validator now passes with `formalism-smoke-h-after` as the latest phase.

5 Whys:

1. Why did H6 fail? The validator flagged `guaranteed uptake`.
2. Why was that wrong? The phrase occurred inside a negated non-claim boundary.
3. Why did the checker miss that? It only matched exact negation strings.
4. Why was exact matching insufficient? Runtime outputs can express the same boundary with nearby
   negation and conjunction.
5. What prevents recurrence? A local unnegated-phrase check that keeps overclaim detection but
   tolerates semantically negated boundary language.
