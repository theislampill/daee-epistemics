## Systems-Security / SOC / Runtime-Governance Findings

Release-blocking findings: none.

Non-blocking findings patched before commit:

- Exact forbidden legacy source-audit/protocol/checker path names were removed
  from a release-gate comparison report and replaced with a generic boundary
  statement.
- README package guidance was changed from machine-specific shell wording to portable
  archive-entry guidance.
- A nomenclature normalization source was added so routing/state/Level 3 terms
  have one release-facing canonical map instead of ad hoc campaign vocabulary.
- The nomenclature source was converted to ASCII-safe terminology after a
  mojibake issue was detected.

Later hardening:

- Level 3 remains a bounded executable routing pilot over the covered genera,
  not a catalogue-wide deterministic router. Future expansion should add
  owner-faithful trigger rules, not owner packs or broad source parade.
- `check_execution.py` rejects shallow first-burden-only outputs when a
  `continuation_queue` is licensed. Deeper anti-padding detection can still be
  hardened later with semantic scoring, but the current checker already requires
  owner-floor markers, B.s, Land(B), R(H,Delta), continuation traversal, and
  closure-gate discipline.
- Feature extraction is intentionally span-backed and partly heuristic. This is
  acceptable for the v0.3.2.0 claim as long as release language remains
  "deterministic routing given features" rather than deterministic diagnosis.

No issue:

- `route.py` makes no LLM calls and is deterministic given `features.json`.
- `diagnose.py` separates deterministic/span-backed features from ambiguous
  interpretive fallbacks.
- `reconstruct.py` validates route-plan reconstructibility instead of routing.
- `validate.py` checks route-plan integrity and ontology licensing.
- `check_execution.py` meaningfully fails missing owner-floor, missing
  B.s/Land/R, shallow continuation, and closure defects.
- `daee_level3.py` no longer writes an executable prompt when validation or
  reconstruction blocks execution; it writes a visible blocked/PARTIAL artifact.
- Grief/register HOLD remains preserved in the bundled fixtures.
- Generated runtime files are reproducible from atomics through the build
  pipeline.
- User-machine assumptions are excluded from intended release
  surfaces.
- CI/workflow surfaces are maintainer validation only and are not required for
  ordinary skill use.

## Salafi/Athari Theologian + LLM-Runtime Findings

Release-blocking theological/runtime findings: none.

Non-blocking findings patched before commit:

- Added a durable nomenclature map documenting `Athari/Salafi` normalization and
  the relationship between `Athari`, `Salafi`, `Taymiyyan`, and `Wahhabi` as
  broad internal routing aliases, not public source-branding.
- The same map states that `Ashari` and `Maturidi` are varied families rather
  than monolithic noetic states.
- The transliteration table was made ASCII-safe for release portability while
  still documenting readable prose aliases.

Later hardening:

- Broader doctrinal, testimony, moral-protest, and fitrah routing coverage
  should extend the executable trigger matrix through owner-file-faithful rules.
  It should not add quotation-bank behavior, source parade, polemical clutter, a
  codon DSL, or new route families.
- The route matrix should continue to be checked against owner-floor operations
  as more TTPs become executable Level 3 rules.

No issue:

- Sound reason vs reason-as-tribunal discipline is preserved: imported criterion
  and hidden tribunal features route through FPD/M1 before first-order V2 proof
  dumping when span-backed.
- Wahi/revelation authority is not subordinated to imported philosophical
  tribunals in the Level 3 release claim or runtime governance.
- Fitrah/restoration, daruri/nazari proof demand, grief/register HOLD, genuine
  shubhah after deformation clearing, false resemblance, and doctrinal
  predication remain distinct in the covered fixtures and owner surfaces.
- FPD/M1/V2/R1/R2/R3 boundaries are sufficient for the v0.3.2.0 pilot claim.
- `/daee-epistemics [input]` remains the user-facing path; scripts are a bundled
  execution layer when available, not a burden placed on ordinary users.
- Scriptless fallback is visibly documented as Level 1/2.
- Fixture 18 / highest-complexity sustained render-through limits remain bounded
  as transformer execution limits, not specification success.
- The release docs do not claim pure-Hermes parity, deterministic feature
  extraction, codons, owner packs, or guaranteed all-runtime Level 3 behavior.
