## What A.13 Would Change

Current Diagnostic IR register handling is schema-light. The runtime and
checkers infer or reconcile live register obligations from Layer A,
`field_witness.register_deltas`, normalized activation records, owner
activations, and convergence evidence. The hard register set
`heart`, `xi`, `Omega`, `mu`, and `kappa` is formal and checker-consumed, but it
is not yet a required canonical Diagnostic IR object.

A.13 would introduce a version-gated hard-register Diagnostic IR contract. The
proposed design adds a new schema version and a canonical `registers` object:

```json
{
  "diagnostic_ir_schema_version": "0.4.3-hard-registers-v1",
  "registers": {
    "heart": { "state": "non_live", "functions": [], "basis": [], "non_live_reason": "not-diagnosed" },
    "xi": { "state": "live", "functions": ["warrant-authority"], "basis": ["..."] },
    "Omega": { "state": "live", "functions": ["ontology-predication"], "basis": ["..."] },
    "mu": { "state": "live", "functions": ["memetic-carrier"], "basis": ["..."] },
    "kappa": { "state": "live", "functions": ["dependency-collapse"], "basis": ["..."] }
  }
}
```

This affects A.10/A.12/B.5 because hard register fields would make "same live
register set" and decode/reconstruction obligations machine-readable rather
than schema-light/inferred. After A.13, reproducibility and NLA decode lanes
could compare canonical register state directly, and full IR-state decode would
have a concrete register schema target.

Even after A.13, the repo would still not claim guaranteed `T_lang` uptake,
cross-host/paraphrase reproducibility, model-smoke completeness, or full release
provenance unless those lanes are separately opened and proven.

## Proposed A.13 Migration Shape

Smallest safe migration slices:

1. Owner accepts or revises the design in
   `docs/audits/v0.4.3.0-a13-hard-register-schema-migration-design.md`.
2. Add dual-version schema support. Historical schema-light artifacts remain
   valid; hard-register artifacts must declare the new schema version.
3. Update `tools/check_ir_instance_integrity.py` to validate hard-register
   objects only under the new schema version.
4. Update `tools/check_register_formalism_bridge.py` so hard-register fields
   remain rejected for schema-light projections but are allowed and checked for
   the hard-register version.
5. Add positive/negative fixtures for all five registers.
6. Only after checker/schema fixtures pass, update runtime emission and fresh
   governed proof.
7. Then update reproducibility and NLA decode lanes to consume canonical
   register state.

## Benefits

- Makes live register state machine-checkable instead of inferred.
- Gives A.10 NLA isomorphism a direct canonical live-register comparison.
- Gives A.12 reproducibility a hard register-field comparison target.
- Gives B.5 full IR decode an explicit schema target.
- Reduces ambiguity around register-accounting completeness.

## Risks

- A broad migration could break historical schema-light fixtures if not
  version-gated.
- `tools/check_register_formalism_bridge.py` currently rejects hard register
  schema fields; that guard must become version-aware, not weakened.
- Runtime emission should not be patched before schema/checker fixtures prove
  the contract.
- The first A.13 slice should not accidentally migrate unrelated source-status
  or `sigma` semantics into the hard-register object.
