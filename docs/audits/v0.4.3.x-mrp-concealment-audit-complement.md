## High-level conclusion

The audit correctly identifies two live regressions in the retained smokes:

- `message(61).txt` pre-declared downstream burdens in Layer A / held state but later labeled closure-witness MRP edges as `generated_burden_instantiation`.
- `message(62).txt` rendered `concealment: None detected` while the same Layer A block marked D6 imported-framework and D3 identity-stabilization pressure as operative.

Current owners say Layer A owns first-pass burden discovery and held material; MRP is a post-landing reread/resultant gate that may activate held burdens, generate new burden nodes, hold partials, loop-break, or close.

## Architecture match

The safe patch aligns with the existing chain:

`Layer A / initial state-read -> Layer B -> Land(ⁿB) -> [Mid-Reread Pressure] -> R(H,Δ) -> MRP resultant -> Closure/Reconstruction Witness`.

It preserves repo-native notation: `¹B`, `²B`, `MRP(¹B)`, `R(H,Δ)`, `∇·T`, `∇×T`, `∇·B`, `∇×κ`, `𝒞(Ψᴺ)`, and `T_lang`.

## Architecture risks

- Making MRP generation-first would lose reconstructible initial burden accounting and could cause missed input-anchored burdens.
- Treating all named-worldview cases as a determinate interior kufr mode would over-certify unseen states and violate the existing lexical-vs-sharʿī caution.
- Treating `clear` as impossible would break valid genuine-shubhah / already-cleared cases.

## Minimal safe patch set

- Add worked counter-case text for held-vs-generated MRP route typing.
- Teach checkers to parse Markdown-styled MRP blocks and closure-witness MRP resultants.
- Add a five-node held-route fixture and a closure-ledger regression fixture.
- Add a narrow concealment-mode checker and fixtures for surface-open / framework-concealed cases.
- Preserve `clear` for positively non-operative concealment and preserve `mode-?` for unresolved interior mode.

## Deferred

- Full concealment `type` / `level` schema expansion.
- A numeric cap on Layer A burden inventory.
- Reframing the dependency graph as MRP-only rather than closure-witness / field_witness reconstructed.

## Corrective proof addendum

After the bounded patch, the implementation was re-audited against the stronger behavioral
goal: MRP must operate as a live post-Land reread / escape-route gate, not merely as a
closure-ledger label checker.

### Observed faults

- `khaybar-input.md` initially produced MRP blocks where `Field diagnostics:` prose substituted
  for the literal `Route-gradient:` and `MRP route result type:` fields.
- `j173-input.md` initially rendered bare `concealment: clear` while later MRP prose identified
  Trinitarian person/nature grammar as a hidden-framework recoil.
- `TST-input.md` produced a structurally valid closure witness using superscript burden notation,
  but the graph parser only accepted `B1`-style IDs.

### Causes

- The generated runtime template still permitted adjacent route prose to stand where required
  MRP route fields should have appeared.
- The concealment checker only inspected the immediate Layer A block and did not treat later
  hidden-framework recoil as evidence that `clear` was unlicensed.
- Closure-witness parsing did not normalize public `¹B` notation to machine `B1` notation.

### Source-owned fixes

- Strengthened the root skill and generated runtime template so every compact MRP block must
  render literal `Route-gradient:`, `MRP route result type:`, and `MRP resultant:` lines.
- Strengthened concealment-mode guidance so surface-open Trinitarian/person-nature imports,
  doctrine-import pressure, named-worldview pressure, and pseudo-neutral tribunals require a
  non-clear `Concealment mode:` unless the output positively explains that the framework no
  longer governs.
- Added superscript-before-B normalization to closure witness parsing.
- Added checker guards for route-gradient presence, generated-vs-held lineage, concealment-mode
  leakage, and field_witness `reread_pressure.route_gradient` / `route_result_type`.
