## Andon GATE47-TRINITARIAN-FORMAL-REREAD-HELD-GENERATED-MIRROR

Symptom:
The Trinitarian matrix output preserved under
`.daee/release-regression-smokes/20260604-150430-matrix-trinitarian-j173/output.md`
shows visible generated-held MRP diagnostics for `B6` as non-neutral and
unresolved, but the generated Stage 07 formal reread scaffold defaulted all
rows to `divergence_state="neutral"` and `curl_state="null"`.

Failed check:
`python tools\check_mrp_generated_burden.py --outputs .daee\release-regression-smokes\20260604-150430-matrix-trinitarian-j173\output.md --show-advisories`
reports `formal_reread_states[6]` divergence/curl disagreement with visible
`∇·T` and `∇×T`.

Owner file / owner surface:
`tools/run_staged_current_skill_smoke.py` `stage07_formal_reread_states()`.
The checker remains strict; the historical output was not hand-edited.

5 Whys:

1. The preserved output failed because the JSON formal reread state did not
   mirror the visible generated-held MRP field diagnostics.
2. The mismatch existed because the producer initialized every formal reread
   row as neutral/null, regardless of unresolved generated-held state.
3. The system allowed it because visible MRP rendering already had a
   `held_or_partial` predicate, but the JSON mirror did not reuse that state.
4. Earlier canaries checked JSON null and source registration, but did not
   assert the generated-held field-state mirror on the producer helper itself.
5. Recurrence is prevented by deriving JSON `divergence_state` and
   `curl_state` from the same held/unresolved predicate used by the visible
   MRP scaffold, plus a self-test that fails if generated-held rows regress.

Hansei:
Field-witness JSON is not a summary channel; it is a reconstruction mirror.
When public MRP carries HOLD/PARTIAL/RECURSE, the formal reread state must
remain open too.

Countermeasure:
`stage07_formal_reread_states()` now emits `non-neutral` / `unresolved` for
held or partial rows and keeps `neutral` / string `"null"` for landed rows. The
self-test now asserts the B1-B6 generated-held case mirrors the visible
non-neutral/unresolved diagnostics.

Smoke B command/result:
`python tools\run_staged_current_skill_smoke.py --self-test`: PASS.
`python tools\check_mrp_generated_burden.py`: PASS with `16` valid and `31`
invalid fixtures after the companion M9 canary was added.

Remaining blocker or closure:
Source countermeasure closed. The historical Trinitarian output remains
negative evidence and still must not be promoted; a fresh model output is
required before claiming Trinitarian Stage 07 pass.

`M9-predication-mode.sense-split` for a real M9 sense/referent/predicate

`python tools\check_mrp_generated_burden.py --outputs .daee\release-regression-smokes\20260604-150430-matrix-khaybar\output.md --show-advisories`
failed with:
`ACT B3_3 operation 'sense-split' is not a registered source-owned operation for 'M9-predication-mode'`.

Owner file / owner surface:

checked against `atomics/skill/references/tactics/M9-predication-mode.md`.

   checker registry.

   the owner file's operation floor explicitly requires sense/referent/
   predication splitting.

   negatives but no positive M9 `sense-split` fixture.

   `predication-repair` and did not include the Khaybar source-stack shape.
5. Recurrence is prevented by registering `sense-split` with a narrow body
   regex tied to M9's source contract and adding a positive fixture that must
   still perform real sense/referent/predication work.

Checker strictness must be source-owned, not alias-starved. Rejecting invented
operations is correct, but a strict checker must include real owner operations
that the owner source requires.
