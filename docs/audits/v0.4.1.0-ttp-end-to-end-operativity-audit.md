## Safe Patch Made In This Pass

Added `tools/check_ttp_operator_contracts.py` as a baseline guard. It checks catalogue owner
resolution, front-matter identity, catalogue registration, audit JSON parity, field-target
language, and known forbidden operator claims. It is intentionally not a strict full-contract
checker yet, because the audit finds the full runtime-operator contract is uneven and needs a
phased owner patch before a strict gate can honestly pass.

## Patch Recommendations

### Phase 1 - Template/header fields
Add a minimal `Runtime operator contract` section to high-risk owners first, not all files blindly. Required fields: Activation; Field target; Burden/submove form; Delta effect; Possible nabla reread; `R(H,Delta)` obligation; Hold/release/closure effect; Output boundary; Negative constraints; Fixture/checker.

### Phase 2 - High-risk TTP owner patches
Prioritize owners with missing `R(H,Delta)` plus missing fixture coverage, and long case-library owners whose family-local load floors can accidentally read as topic banks.

### Phase 3 - Checker/fixture coverage
Add class-level structural fixtures for field-accounting compatibility. Do not create exact-output burden-order fixtures. Add negative fixtures for scalar closure, nabla-as-Delta replacement, and proof-by-symbol drift.

### Phase 4 - Docs/index and reference sync
Once owner contracts are patched, regenerate docs/index and pipeline pages so public navigation continues to reflect owner truth rather than becoming a second owner.

### Phase 5 - Release package refresh
Only after owner patches and checks pass, rebuild the compiled runtime and provenance from the final commit.
