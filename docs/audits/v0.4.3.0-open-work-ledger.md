## Group A - Formalism Proofing

### A.1 - Formal Termination Proof for the MRP Generation Chain

What it is: A written theory-document proof that the sequence of state
transitions `Sᵢ -> Sᵢ₊₁ -> ...` terminates, using the small-step state:

```text
S = (N_space, N_sel_or_held, B_live, H, κ, Reg, Routes, SourceBasis, Gate, RenderGate)
```

Why needed: The architecture currently relies on LoopBreak, finite catalogue,
and depth ordering as engineering intuition. The claim that `𝔅_MRP` is
exhaustible needs a formal proof.

Required proof steps:

1. The eligible route set `R(S)` is finite at every `S`, because it is bounded by
   the finite owner catalogue and the IR/routing/owner gates that constrain `∇`.
2. Every `operate` step (`ⁿBᵢ[OP] -> Sᵢ'`) either reduces `|B_live|` when a
   burden lands, or increases the generation depth `d(B')` of a generated burden.
3. Generation depth is well-founded:
   `d(B) = 0` for `B ∈ 𝔅_LA`; `d(B') = d(B) + 1` when `B'` is generated by
   `Land(B) + R(H,Δ)`. No generated burden has `d = 0`; no infinite chain has
   decreasing `d`.
4. LoopBreak is a partial transition (`⇀`, not `->`): it fires only under
   diagnosed `∇×T ≠ 0` and requires an owner-licensed non-circular ground. It
   cannot loop; it resolves the circular dependency that triggered it, reducing
   `|κ|` or resolving a `κ` cycle.
5. From 1-4, the computation sequence reaches `STOP`, `HOLD`, or `PARTIAL` in
   finite steps.

Done looks like: The proof is written in
`docs/algebraic-notation-and-noetic-formalism.md` or the designated theory
spec, not only in implementation comments. It references the state definition,
operator typing table, and LoopBreak partial-transition symbol (`⇀`).

Unblocks: A.2, A.3, A.4, and B.1.

### A.3 - Lemma: `∇·B = neutral` Implies `𝔅_MRP` Exhaustion

What it is: A definitional proof:

```text
∇·B is the post-Δ diagnostic predicate over the burden field B.
B_live = {B ∈ 𝔅_total : terminal_state(B) = none} after traversal.
If B_live ≠ ∅ after traversal, outward burden-field pressure exists.
Therefore ∇·B ≠ neutral.
Contrapositive: ∇·B = neutral -> B_live = ∅ after traversal.
B_live = ∅ after traversal -> every B ∈ 𝔅_MRP is terminal.
Therefore ∇·B = neutral -> 𝔅_MRP is exhausted.
```

Why needed: The architecture asserts that `collapse_positive` subsumes MRP
exhaustion, but the proof is not written. Without it, an output could claim
`∇·B = neutral` while MRP burdens remain unworked.

Done looks like: A formal lemma named "MRP Exhaustion Lemma:
