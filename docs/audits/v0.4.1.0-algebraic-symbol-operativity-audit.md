Gate rule: a row proves operativity only through owner, classification, default/audit visibility, fixture/checker proof, and a named control effect. Broad prose tokens alone are not proof.

## Approved Classifications

- OPERATIVE: changes a runtime control surface.
- AUDIT_DIAGNOSTIC_ALLOWED: visible in audit/formalism mode only with a control effect.
- DEFAULT_RUNTIME_FORBIDDEN: must not appear as default user-facing runtime notation or proof language.
- DEFAULT_COMPACT_STATE_MARKER_ALLOWED: may or must appear in default output only as short, control-bound governance state.
- DEFAULT_FORMALISM_EXPOSITION_FORBIDDEN: long explanatory formalism or alias-heavy jargon is forbidden in default output.
- DOCS_ONLY: explanatory only, with no runtime-operativity claim.
- HISTORICAL_ONLY: preserved only as provenance/history or ordinary prose not tied to the operator family.
- ORNAMENTAL_RISK: at risk of symbol theater unless demoted or patched.
- NEEDS_PATCH: missing classification, owner, or proof and therefore release-blocking.

## Default Runtime Absence Proof

Generated default-runtime surfaces may print compact target-explicit `∇·` / `∇×` state markers
only when they are control-bound field diagnostics, for example `∇·κ`, `∇×κ`, `∇·B`, or `∇×ξ`.
They must not print long formalism exposition, alias-heavy operator explanations (`del-dot`,
`del-cross`, `nabla dot`, `nabla cross`), decorative proof-by-symbol language, or untargeted
scalarized `∇` claims. The raw expanded register formula may appear only inside generated owner
instructions that explicitly say not to print it by default or mark it as formal/spec notation.
Shannon/NLA terms must not appear as truth, meaning, warrant, revelation, fitrah, or
sound-reason metrics.
