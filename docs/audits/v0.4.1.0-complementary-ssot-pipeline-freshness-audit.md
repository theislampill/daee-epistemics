pipeline, runtime, release, and formalism claims. SSOT means one owner per
responsibility, not one file that contains all truth. The standard used here is:


## Pipeline-Diagram / Framework-Pipeline Freshness

The owner-corrected pipeline has two phases that must not be collapsed:

```text
internal intake / diagnostic control:
D0 input -> always-load -> V1 diagnostic gate -> Phase 1 listening
-> Phase 2 mandatory passes -> Diagnostic IR
-> selected/held N + live registers -> gate checks -> routing precedence
-> selected live burden -> operative submoves -> Delta-nB / Delta-kappa
-> Land(B)

visible release / closure control:
output-release -> diagnostic-render-contract
-> noetic-field banner as first visible output obligation
-> Layer A -> bounded Layer B -> state/noetic reread
-> R(H,Delta) -> STOP / HOLD / RECURSE / PARTIAL
```

The noetic-field banner is not a diagnostic-reduction step. It is a visible
first-output obligation produced from the same classification state as Layer A
after output-release and render-contract governance. The framework chart now
shows it as a render obligation rather than as fake upstream computation.

## NLA Freshness

Public architecture surfaces now state that NLA means Natural Language
Autoencoder, not generic linear algebra and not Shannon theory. The AV /
activation verbalizer analogue is Layer A / Diagnostic IR / noetic-field banner;
the AR / activation reconstructor analogue is reconstruction/reread through
`R(H,Delta)`. Reconstruction fidelity gates closure by recovering selected/held
N, live registers, burdens, owner/TTP eligibility, kappa/H, and closure state.
Confabulation, excessive expressivity, lack of grounding, degenerate bottleneck,
and reconstruction failure force PARTIAL/RECURSE or checker failure.

The framework-pipeline runtime chart intentionally does not print NLA jargon,
because NLA remains audit/formalism visibility and default-runtime jargon is
blocked by render/register checks.

## Divergence/Curl Freshness

Public architecture surfaces now state that `Delta-nB` and `Delta-kappa` are
event-local transition operators, while `∇·` / divergence and `∇×` / curl are
field-level diagnostics over Delta-produced burden/dependency state. Compact
`∇·κ` / `∇×κ` state markers are default governed output when control-relevant;
long formalism exposition remains audit/formalism-only. They are operative only
where they affect dependency pressure, loop-breaking, `R(H,Δ)`, or
PARTIAL/RECURSE/COMPLETE.

The framework-pipeline runtime chart intentionally does not print the raw
operator family because the default runtime must not surface it as notation
theater.

## 5 Whys: Framework Chart Drift

1. Visible defect: the active generated chart used active-looking Level 3 wording and omitted explicit current noetic-banner/register/delta nodes.
2. Why it happened: the YAML chart lagged behind newer owner semantics and the generator hardcoded visual nodes.
3. Why the checker did not catch it: `check_framework_pipeline.py` checked freshness of the generated block and many broad structural tokens, but did not require the new composed truthmakers or scan active public surfaces.
4. Why release/report prose allowed it: release reports could cite checker pass without proving the chart represented the current owner complement set.
5. Recurrence block: YAML now carries owner-backed nodes and support claims; generator renders them; checker requires them and scans active surfaces for stale Level3/Pipeline-label/source-runtime drift.

## 5 Whys: Public Diagram Boundary Drift

1. Visible defect: `docs/index.html` and `docs/daee-epistemics-pipeline.html` did not distinguish algebraic formalism, divergence/curl diagnostics, NLA reconstruction fidelity, and package/runtime layout clearly enough.
2. Why it happened: public diagrams repeated a compressed architecture story without carrying the latest audit boundary qualifiers.
3. Why owner/checker did not catch it: formalism and NLA gates checked owner/audit surfaces and default runtime absence, not public architecture pages.
4. Why release/report prose allowed it: "architecture map" language was treated as explanatory, not release-facing claim surface.
5. Recurrence block: `check_framework_pipeline.py` now checks public architecture pages for NLA AV/AR mapping, divergence/curl default-runtime boundary, ignored generated runtime, and raw-atomics-not-packaged wording.

## 5 Whys: Release Provenance Status Drift

1. Visible defect: local v0.4.1.0 docs still said corrected artifact replacement was pending after the release/provenance sync had already occurred.
2. Why it happened: a later hard-stop shifted the task back to local audit without reconciling the earlier remote mutation state.
3. Why owner/checker did not catch it: release-claim audit was accepted before the final sync and remained historical.
4. Why release/report prose allowed it: "candidate" and "published replacement" were stored in different surfaces without a fresh trace.
5. Recurrence block: the release docs now distinguish current public asset/provenance from historical candidate state, and the framework checker requires v0.4.1.0 release surfaces to carry final commit/SHA/published-replacement tokens when used as current release claims.

## Poka-Yoke / Checker Changes

`tools/check_framework_pipeline.py` now fails when active pipeline/public surfaces:

- use Level3 as active render doctrine instead of legacy compatibility;
- use Pipeline #1/#2 language as active architecture;
- omit noetic-field banner, selected/held registers, Delta transition, bounded Layer B, or `R(H,Delta)` reconstruction from the generated chart;
- describe generated `skill/**` as tracked/canonical source;
- mention NLA in public architecture pages without Natural Language Autoencoder, AV/AR, reconstruction-fidelity, non-linear-algebra, and non-Shannon boundaries;
- omit divergence/curl audit/formalism/default-runtime boundaries from public architecture pages;
- make current v0.4.1.0 release/provenance claims without final commit/SHA/published-replacement support.

The checker also allows `docs/` references in framework chart concept ownership,
because some composed truths, such as generated-runtime layout, are release/audit
truthmakers rather than runtime owner files.
