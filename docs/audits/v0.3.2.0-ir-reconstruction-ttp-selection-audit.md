## Purpose

This audit tests whether the daee-epistemics DSL/IR works as faithful compression rather than
typed commentary. The NLA analogue is:

```text
hidden noetic/discursive burden
-> DSL/IR bottleneck
-> reconstruction/restoration check
-> mechanical fidelity + ontological accuracy
```

The question is not whether a TTP label appears. A TTP is deployed only when the IR makes its
selection reconstructible, the owner floor executes target -> operation -> result, and state
re-read shows what landed or remains live.

This pass does not reopen v15 codons or Level-2 forcing. v15 closed those as not warranted.

## Current TTP Deployment Mechanism

TTP/operator selection currently proceeds through deterministic-with-interpretive-boundaries:

```text
input
-> noetic reading / Phase 2 mandatory passes
-> Diagnostic IR fields
-> gate checks
-> routing-precedence suppression and tie-break rules
-> selected current live burden
-> owner-backed TTP entry
-> target -> operation -> result
-> Land(B)
-> R(H,Delta) / STOP / HOLD / RECURSE / PARTIAL
```

The IR fields that contribute to routing are chiefly:

- `case_family`
- `claim_type`
- `claim_level`
- `pattern_profile`
- `deformation`
- `concealment_mode`
- `do_orient`
- `reason_category`
- `routing_gate`
- `matched_modules`
- `source_basis`
- `restoration_target`
- `next_move`
- optional structural fields: `load_bearing_node`, `collapse_radius`, `intervention_target`,
  `what_is_withheld_and_why`, `what_remains_live`
- `post_render_gate`

The first-live burden is governed by diagnostic reduction, the dispatch gate, and
`routing-precedence.md`. Multiple plausible TTPs are constrained by suppression rules, P7 stops,
concealment/orientation gating, source-basis requirements, owner-entry criteria, and
recursive-state exit criteria.

Selected owner vs nearby held owner is represented by the three-way activation partition:

- absent from `matched_modules` and `what_is_withheld_and_why`: not triggered;
- present in `what_is_withheld_and_why`: triggered but governed-held;
- present in `matched_modules`: active in this pass.

Owner-floor execution is evidenced by source-backed `matched_modules`, `source_basis`, and
case-specific target -> operation -> result work. `tools/check_smoke_artifacts.py` already rejects
hard PASS when it sees generic `Operation: use M1` / label-only operation lines or missing
owner-floor/compiled-floor evidence.

Land(B) and R(H,Delta) are owned by `recursive-state-transitions.md`, with visible render governed
by `output-release.md` and `diagnostic-render-contract.md`. State re-read is enforced through
`post_render_gate`, hard PARTIAL rules, and recursive traversal checkers.

## Routing Architecture Finding

The architecture is **deterministic-with-interpretive-boundaries**.

Deterministic parts:

- schema enums and required fields;
- module catalogue IDs and compiled-module-map paths;
- source-basis and ghost-load checks;
- routing precedence once IR axes are set;
- STOP/HOLD/RECURSE/PARTIAL state rules;
- render and smoke checkers for label-only, generic operation, partial-next-burden, and wrapper
  disclosure.

Interpretive boundary:

- the model forms the noetic read and populates IR axes from the input;
- live burden wording and nearest-neighbor TTP contrast are semantic judgments;
- Sonnet and Hermes may differ if they interpret trigger conditions differently.

Therefore reconstruction can honestly measure faithfulness and within-model stability. It cannot
claim full cross-model deterministic routing equivalence without a separate cross-model
reconstruction campaign.

## Reconstruction Gap

Before this patch, the repo had strong execution and checker machinery, but no explicit
reconstruction verdict. An IR could be schema-valid and source-backed while still not proving
that a separate reader could recover:

- the live burden,
- selected TTP/operator,
- nearest plausible held alternatives,
- expected Land(B),
- governance verdict.

That is the typed-commentary risk. It was not a release-blocking owner-load gap, and it was not a
codon-warranting gap. It was a compact reconstructibility witness gap.

## Reconstructor Design

Chosen design: **mechanical + LLM hybrid**.

Mechanical layer:

- parse structured IR fields;
- check schema shape;
- check catalogue-valid `matched_modules`;
- check source-basis coverage and ghost-load absence;
- check post-render gate consistency;
- check bounded stability thresholds on captured routing states.

Semantic layer:

- a separate no-skill reconstruction pass receives only the original input, populated IR/trace
  candidate, and reconstruction criteria;
- it does not receive `SKILL.md`, the module catalogue, the routing catalogue, owner files, or
  compiled maps;
- it judges whether the IR faithfully compresses the noetic burden rather than reconstructing
  from skill knowledge.

Cross-model reconstruction is stronger but heavier. It remains optional release-grade evidence:
Hermes IRs may be reconstructed by Sonnet and Sonnet IRs by Hermes when available.

## TTP Selection Reconstruction Check

The pass requires the following chain in trace/verdict evidence for selected operators:

```text
burden signal
-> IR field(s)
-> owner trigger
-> selected TTP/operator
-> nearest plausible alternatives
-> why selected TTP is first-live
-> why alternatives are held/rejected/deferred
-> expected Land(B)
-> governance verdict
```

This witness belongs in trace/verdict artifacts or internal diagnostic evidence, not default
public output.

## Required Contrast Fixtures

New static reconstruction fixtures cover the user-required minimum:

| Fixture | Expected routing | Neighbor contrast | Status |
|---|---|---|---|
| Trinitarian claim cluster | V8 + M9 first-live / tightly co-live | V2 deferred | PASS |
| Imported tribunal protest | FPD + M1 first-live | V2 secondary, M8 deferred | PASS |
| Grief-coded objection | P7 + M4 register-hold first-live | V2/V8 held | PASS |
| Imported tribunal repeat 5x | Stable/near-stable state | one M8 neighbor variation allowed | PASS |
| Genuine shubhah after clearing | V9 first-live | M5 held | PASS |
| Mushabara fasida | seven-deformations 1-A + M5 | V2 held | PASS |
| Label without trigger negative | V2 label cannot reconstruct | fails reconstruction | PASS |

The repeatability fixture encodes the requested thresholds:

- stable requires identical `case_family`, `claim_type`, `claim_level`, and semantically stable
  burden across five runs;
- near-stable allows no more than one neighboring owner variation across five runs;
- drift is a routing defect even if individual runs reconstruct.

## Compliance Witness

The witness should live in trace/verdict artifacts, not default public output. Default output
keeps the existing compact Layer A, B.s/Land/R work, and governed prose. A public footer-style
self-witness would add noise and conflict with current render governance.

## Operator Mode / Performance Drift

No new `operator_mode` field was added. The reconstruction pass and output governance already
catch the relevant failure: if an output optimizes rhetoric, engagement, or apologetic display
instead of restoration-state tracking, it will fail to reconstruct burden -> operator -> Land(B)
-> verdict.

## What Remains Deferred

- Cross-model reconstruction is optional stronger evidence, not a required repo-side patch.
- Fixture 18 sustained render-through limits remain capability/driver-bound under prior v14/v15

## Release Implication

Package-bound release smokes may proceed with the existing driver/evidence policy:

- no pure-Hermes parity claim unless hard pure fixtures pass stably;
- keep wrapper/golden/continuation evidence labeled;
- require trace/verdict evidence for owner-floor execution and reconstruction fidelity;
- use live five-run stability checks for release-grade repeatability, comparing routing state
  rather than prose.

v0.3.2.0 can ship with this reconstructibility standard. Further TTP deployment work before
shipping is not required unless package-bound smokes reveal actual drift under the new stability
thresholds or a release-critical owner fails reconstruction.
