## Decision

Level 3 as a public/default execution concept is retired for the v0.4.1.0 candidate workflow.
The optional route/check harness remains live repo/dev machinery, but it still carries historical
implementation names such as `daee_level3.py`, `level3_lib.py`, and
`check_level3_data_shapes.py`.

The safe current action is to remove active push/PR CI execution of the legacy harness and label
the remaining references. A full rename to `runtime-harness`, `dev-harness`,
`route-check-harness`, or similar is rename-required but deferred because it crosses atomics,
generated runtime, build manifests, docs, CI, and tooling.

data-shape invariant for the optional harness.

## Recommended Follow-Up

1. Defer full code/data harness rename until after v0.4.1.0 cleanup unless the maintainer explicitly requests it.
2. If renamed, migrate atomics, generated runtime, build manifest/map, docs, CI, and checker names together.
3. Keep historical release/audit evidence summarized in consolidated history files and mark them through `docs/audits/INDEX.md`.
4. Keep package exclusions for `level3-runs/` until the local run-artifact root is renamed.
