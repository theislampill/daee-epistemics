# v0.3.2.0 v15 Codon / Level-2 Pilot Decision

## Decision

**CODON PILOT NOT WARRANTED**

The v15 Stage 1 adjudication did not surface a codon-relevant failure class. The remaining gaps were proof-case defects, harness false negatives, support-denominator bookkeeping, and two bounded no-usable-output owner proof cases.

No YAML codon pilot was run.

## Gate Standard Applied

A codon or Level-2 forcing pilot would be warranted only if both were true:

1. Hermes pure outputs on cases where Sonnet selects Level 2 observably default to Level 1 ordinary prose despite objective Level-2 triggers.
2. Stage 1 did not already explain the failure as proof-case defect, harness denominator issue, governance-correct HOLD, or ordinary proof metadata/no-output behavior.

The evidence does not satisfy that standard.

## Evidence Compared

### Sonnet Golden

The Sonnet golden behavior remains stronger sustained burden traversal: it keeps a burden stack, delays closure, renders repeated B.s/Land/R cycles, and continues until the hard case is more fully exhausted.

This is a depth/continuation behavior delta, not proof that Hermes cannot enter Level 2.

### Hermes Pure v14/v15

Hermes pure hard fixtures still fail stable hard-depth:

- fixture 10 remains stochastic
- fixtures 11 and 18 remain stable PARTIAL
- additional hard/complex fixtures remain PARTIAL

But the outputs are not merely Level-1 ordinary prose. They emit IR-like headers, current bounded operators, owner-family routing, Target/Operation/Result work, Land(B), and R(H,Delta) in many cases. The first failing boundary remains render-through / continuation depth, not Level-2 entry.

### Owner Proof Adjudication

Stage 1 owner adjudication found:

- no missing owner files
- no missing generated bundle paths
- no compiled-module-map defects
- no owner-loadform defects
- no release-blocking routing defects
- 32 of the 34 v14 PARTIAL gaps moved to PASS or durable non-operative support classification after proof/harness fixes
- 2 remaining gaps are no-usable-output proof cases, not owner-load or Level-2-entry failures

### Fixture 18

Fixture 18 continues to show the established capability boundary: Hermes enters the governance/control-surface route but compresses and stops before hard traversal completes. Across v10-v15 this has not behaved like a missing Level-2 trigger. It behaves like render-through / continuation-depth limitation.

### SKILL.md and Runtime Dispatch Gate

The current root/runtime surfaces already require owner-body or compiled-section evidence before hard B.s execution. They distinguish SKILL.md recognition from owner-floor execution and require PARTIAL/OWNER-BODY-NOT-LOADED when owner evidence is absent.

Adding a new codon layer would mostly rename existing execution-state obligations rather than solve a proven entry failure.

### Output Governance and Checker Expectations

The smoke checker already rejects:

- label-only hard PASS
- generic owner-floor evidence as hard PASS evidence
- wrapper-dependent output promoted as pure/native
- hard PARTIAL without missing state / next-burden judgment

v15 harness fixes further separated target-owner execution from downstream HOLD. Existing trace/verdict machinery is sufficient for the failure class found.

## Level-2 Entry Finding

**LEVEL_2_FORCING_NOT_WARRANTED**

Hermes is not reliably reaching Sonnet-style hard depth, but the current evidence does not show primary Level-2 entry failure. It shows:

- owner and compiled sections are available/addressable
- owner proof can retrieve and execute owner-floor work after proof metadata is corrected
- hard fixture outputs often enter Level-2-shaped routing and operation surfaces
- failures persist at render-through and continuation depth

The capability-bound boundary on fixture 18 is established. No further specification work is owed against fixture 18 in v15.

## Why Codons Are Not Warranted

Codons would be warranted only for a positive failure class such as:

- owner retrieval obligations not visible enough from SKILL.md
- owner-floor execution needing an emit-visible proof surface not expressible today
- HOLD_GOVERNED vs missed-owner not provable with trace/verdict machinery
- PARTIAL_NEXT_B / CONTINUE_FROM_R needing a compact protocol not already present
- render-through obligations compressed despite existing checker/trace enforcement
- label-only rejection materially improved by codonized evidence

Stage 1 surfaced none of these as the primary remaining issue. A codon layer would add a second syntax for existing obligations and risks decorative emission.

## Final Decision

**OWNER GAPS BOUNDED — CODON PILOT REJECTED**

Exact next action: keep the v15 owner adjudication and denominator bookkeeping; proceed to package-bound release smokes only under the existing driver/evidence policy, without pure-Hermes parity or catalogue-wide overclaims.
