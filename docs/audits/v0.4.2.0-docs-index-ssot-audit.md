# docs/index SSOT Audit

## Executive verdict

INDEX ACID/SSOT/GRASP HARDENED; TARGETED P2 GENERATION REMAINS OPTIONAL

The visible Architecture rows/cards and Theory notation now derive from the shared runtime architecture projection at `docs/index/runtime-architecture.json`, and the Owner/TTP module table derives from `atomics/skill/references/diagnostics/module-catalogue.json`. This pass closed the stale embedded Reference Library snapshot risk by generating `REFS`/`DOCS` from atomics source at build time and removed dead release-status JavaScript that carried old smoke/release wording.

Follow-up P1/P2 status: the Architecture interactive trace maps and Owner/TTP family/operator maps remain curated JavaScript, but they are now mechanically parity-checked against their owners by `tools/check_docs_index_interactions.py`. The checker also verifies the three intended runtime renderings: the Architecture plain row, the Architecture formal row, and the distinct Theory Deep Dive notation/mapping rendering all derive from `docs/index/runtime-architecture.json` without becoming text-identical. Full generation of trace/operator prose remains optional hardening rather than an unguarded drift risk.

Additional poka-yoke added in this pass: large JavaScript constants that contain runtime/control claims must be declared in `docs/index/manifest.json` with `js_constants` coverage. New large runtime/control constants fail the interaction checker unless a manifest/checker/source-basis entry covers them.

Design-system update: docs/index visual identity is now owned by `docs/index/DESIGN.md`, a scoped Google DESIGN.md-inspired source with YAML token front matter and Markdown rationale. `tools/build_docs_index.py` emits CSS custom properties from that file, and `tools/check_docs_index_interactions.py` validates required token groups, stage colors, token references, carousel token usage, focus/reduced-motion coverage, manifest design-source declaration, and lightweight contrast sanity checks. Runtime semantics remain owned by `docs/index/runtime-architecture.json` and atomics/runtime owners; generated HTML remains non-canonical.

Final consolidation update: the docs/index visual/interaction pass restored the intended selected-primary Architecture carousel, fixed card-4 dense example/LoopBreak/Decision containment, and restored Theory card-to-notation interaction. Theory cards now declare `theory_card_notation_targets` in `docs/index/runtime-architecture.json`; the generator emits card `data-notation-targets` and notation `data-notation-id` attributes; the checker fails if card mappings drift, targets are missing, or the cards regress to static display-only panels. Local visual verification confirmed Architecture cards 4/5 are readable when selected, side cards are scaled actual-card previews, the Decision grid renders 2x2+COMPLETE, Theory card click/keyboard activation highlights the corresponding notation, and the Architecture plain/formal rows remain on the Architecture tab.
