## What Counts As Broad Matrix Work

Broad governed/model matrix work means running or promoting governed outputs
to test case-family breadth rather than a single owner-free checker/fixture
slice. It includes any lane that:

- invokes the current skill/model for new outputs;
- selects a new prompt family to exercise broad default runtime behavior;
- claims broader case-family adoption for B.1/B.2/C.5-C.7/D.2/D.3;
- attempts cross-host, paraphrase, package-bound, or release-bound proof;
- treats retained corpus breadth as a release/provenance claim.

This work is protected because structural validator success can otherwise be
mistaken for expert prose/scope fulfillment.

## Candidate Paths

### Option 1 - Read-only existing-artifact scout

Inspect current retained corpus, hard-smoke corpus, ignored `.daee` smoke
artifacts, Grapher sidecars, collapse certificates, and orchestrator notes.

Allowed:

- no source mutation;
- no model calls;
- no package/release/provenance actions;
- exact mapping of existing artifacts to residual rows;
- identification of one already-existing artifact that may be promotable under
  the retained proof-corpus promotion rules.

Stop condition:

- no suitable artifact exists;
- any candidate lacks raw input, governed output, checker-owned certificate, or
  warning-clean Grapher evidence;
- candidate would require expert prose/scope repair or model rerun.

### Option 2 - Bounded single-family governed/model smoke

Run exactly one new governed prompt family with the current skill/model and
retain it only if it passes the required proof stack.

Allowed only after owner approval of:

- case family;
- prompt count;
- model/harness boundary;
- row targets;
- required validator stack;
- expert scope review requirement when used as hard-output evidence.

Stop condition:

- harness failure;
- checker regression;
- graph/certificate/Grapher warning;
- expert scope `PARTIAL` or `FAIL` if the case is used as hard-output proof;
- any pressure to turn the run into a broad campaign.

### Option 3 - Defer broad matrix work

Keep the current 18-case schema-light source-boundary corpus as the active
non-release proof boundary. Do not claim broad model-matrix completion.

This is valid if the current goal is source maintenance, checker/fixture
hardening, docs truthfulness, or later A.13/full-IR decision work rather than
case-family breadth.

## Required Evidence If Later Authorized

Any future broad matrix proof artifact must include:

- raw input sidecar;
- governed output;
- checker-owned collapse certificate;
- warning-clean certificate-backed Grapher HTML;
- retained-corpus manifest entry if promoted;
- SHA256 hashes recorded in the orchestrator;
- applicable validator stack for the target rows;
- expert prose/scope review when the artifact is used as hard-output or
  Brandolini-style proof;
- explicit distinction between structural validators, Grapher
  reconstructibility, and expert prose/scope fulfillment.

## Recommended Option

Recommend Option 1: authorize a read-only existing-artifact scout before any
model-smoke campaign.

Reason:

- It may find promotable evidence already present in `.daee` or retained
  sidecars.
- It preserves the no-model boundary.
- It prevents unnecessary new model outputs.
- It gives the owner a concrete case-family choice if a later bounded model
  smoke is genuinely needed.
