### Invocation Behavior

`atomics/skill/SKILL.md` and generated `skill/SKILL.md` state that
`/daee-epistemics [input]` uses Level 3 whenever bundled scripts are available.
There is no seriousness/deformation gate. Scriptless fallback is visibly labeled:

```text
Level 1/2 invocation - Level 3 wrapper unavailable in this runtime
```

Ordinary users are not asked to inspect `route_plan.json`; SKILL.md gives Codex
the orchestration flow.

### Packaging Behavior

`tools/compiled_runtime_lib.py` copies Level 3 data, scripts, tests, and README
from `atomics/skill/` into generated `skill/` through `RUNTIME_METADATA_COPIES`.
Generated files were regenerated with the build pipeline; no generated skill
files were hand-edited.

### Deterministic Routing Claim

`route.py` consumes `features.json`, `trigger-matrix.json`, and
`routing-precedence.yaml`. It performs no LLM call. Repeat routing over the same
TST `features.json` produced identical route-plan file hashes:

```text
FEF52620E80C59D50F72F1E1102FCED438D3620E8B38C417FA6C8584037EE280
```

The claim remains limited to deterministic routing given features.

### Feature Extraction Honesty

`diagnose.py` emits mechanical features and span-backed interpretive slots. It
uses ambiguous fallback records for unsupported interpretive slots and documents
feature-extraction limits in `features.json`. It does not claim semantic feature
extraction is deterministic across models.

### Reconstruction / Validation / Execution Checking

- `reconstruct.py` fails when no first-live owner or recoverable live burden is
  present.
- `validate.py` checks owner catalogue presence, trigger-matrix presence,
  governance class licensing, feature prefix licensing, land requirements, and
  input hash agreement.
- `check_execution.py` detects missing first-live owner execution, missing
  owner-floor evidence, missing `Target` / `Operation` / `Result`, missing
  `B.s`, missing `Land(B)`, missing `R(H,Delta)`, held/deferred owner execution,
  and premature closure under non-STOP governance.
- Failure emits `user_visible_banner`, and `daee_level3.py` writes
  `partial_banner.md`.

## Patches Made During Hardening

Four concrete bugs or hardening misses were found and patched:

1. `daee_level3.py` crashed with `SameFileError` when `--input` already lived
   inside `--out`. Patch: skip copying when source and destination resolve to
   the same path.
2. `Refute secularism.` produced no first-live route. Patch: add narrow
   secularism/refutation feature extraction and derive a reconstructible
   `broad secularism reason-repair burden`, routed through existing
   `V2-reconstituting-reason`.
3. `check_execution.py` rejected valid `B.s1` evidence because it only accepted
   `B1.s`. Patch: accept both `B.s` and `B1.s` forms.
4. `check_execution.py` treated the sentence "Closing Formulation is withheld"
   as illicit closure. Patch: detect actual close markers such as
   `Closing Formulation:` / heading forms, not withheld mentions.

No new owners, codons, owner packs, route IDs, PF codes, or render modes were
added.

## Release Implication

Package-bound release smokes may proceed with the honest Level 3 claim:

- deterministic routing given features;
- feature extraction remains span-backed but partly interpretive;
- execution remains transformer-bound;
- users without script execution receive visibly labeled Level 1/2 fallback.

The release candidate should not be committed under the release-gate steer
because the real TST Level 3 smoke does not exceed the Sonnet golden behavioral
standard. The release claim must remain narrowed to Level 3 route stability,
reconstructibility, and execution checking rather than native pure-depth parity
or guaranteed multi-burden superiority.
