### ANDON-20260604-HARDCODING-SEMANTIC-HARD-MRP-PROOF-LOCATION

Symptom: the runner self-test failed after the semantic generated-MRP gate was introduced.

Failed check:

`python tools\run_staged_current_skill_smoke.py --self-test`

Failure:

`semantic hard generated-MRP gate (...) must prove non-empty B_MRP with generated_burden_instantiation or explicit no_new_resultant_proof.escape_routes_checked`

Owner file / surface:

- `tools/check_mrp_generated_burden.py`
- `tools/run_staged_current_skill_smoke.py` self-test generated output

5 Whys:

1. The self-test failed because the new semantic gate rejected a hard source-order output with empty `B_MRP`.
2. It rejected the output because the checker did not recognize the artifact's existing no-new-resultant proof.
3. The checker missed the proof because it read top-level `field_witness.no_new_resultant_proof` and `coverage_proof`, but not `formal_reread_states[].no_new_resultant_proof`.
4. That gap existed because the first countermeasure focused on removing filename gates, not all canonical Stage 07 proof locations.
5. Recurrence is prevented by recognizing no-new-resultant proof in formal reread states while keeping the semantic hard-MRP gate strict.

Hansei:

Semantic gates must align with every canonical proof owner surface. Otherwise a valid proof can be misread as absence and pressure the lane toward path exemptions.

Countermeasure:

`no_new_resultant_escape_proof_present()` now accepts proof under `formal_reread_states[]` and nested `field_state_at_stop`, while retaining the requirements for checked escape routes, neutral field state, empty live burden state, zero dependency residual, and `stop_licensed=true`.
