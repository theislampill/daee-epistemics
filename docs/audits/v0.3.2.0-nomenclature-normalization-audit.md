Normalize release terminology for noetic state, aqidah family labels, DSL/IR,
Level 3, TTP/owner/operator language, transliteration, and smoke/campaign

## Accepted Aliases

- `N_AT`: `N_Athari`, `N_Salafi`, `N_Taymiyyan`, `N_Wahhabi`.
- `N_Ashari`: `N_Ash'ari`, `Ashari family`.
- `N_Maturidi`: `Maturidi family`.
- `feature`: prose-only `signal`.
- `span-backed feature`: `span-backed signal`.
- `deterministic feature`: `mechanical feature`.
- `LLM-assisted feature`: `span-backed interpretive slot`.
- `first_live`: prose `first-live`.
- `continuation_queue`: prose `continuation queue`.
- `R(H,Delta)`: historical prose may contain the Greek delta form, but code and
  checker text use ASCII `Delta`.
- `shubhah`: `shubha`, plural `shubuhat`.

## Intentional Non-Normalizations

- Existing code/API field names such as `first_live`, `continuation_queue`,
  `route_plan`, `reconstruction_fidelity`, and `execution_fidelity` were not
  renamed.
- Historical audit text was not rewritten except where a release-facing document
  contained misleading or forbidden path-specific wording.
- Named hard-smoke and comparison labels remain acceptable inside tests,
  fixtures, smoke reports, and historical audits. They are not accepted as
  operative script/data/runtime-governance vocabulary.

Decisions:

- Normalize release-relevant source/docs now.
- Document accepted aliases where the term is a real code/prose split.
- Leave historical audit language when clearly historical.
- Leave code/API fields unchanged.
- Patch misleading public or operative text.
