# v0.4.1.0 Docs Index Source-Coupling Audit

Status: current candidate, release-blocking until the generated docs-index gates
pass.

Scope: `docs/index.html`, `docs/index/**`,
`tools/build_docs_index.py`, `tools/check_docs_index_interactions.py`, and
`docs/daee-epistemics-pipeline.html`.

This is a coherence pass, not a redesign. The question is:

```text
When owner/source files change, does the generated index update, fail freshness checks, or silently rot?
```

## Generator Character

The current generator is mixed, not mostly owner-derived:

- `OWNER_DERIVED`: the live Owner/TTP module table is generated from
  `atomics/skill/references/diagnostics/module-catalogue.json`.
- `STRUCTURED_SOURCE_DERIVED`: top-level tab registry, generated shells, and the
  standalone pipeline page are driven by `docs/index/manifest.json` and
  templates.
- `CURATED_SUMMARY_WITH_OWNER_REFERENCES`: Architecture and Theory prose are
  curated summaries that cite owner files but do not semantically auto-update
  when those owners change.
- `STATIC_SNAPSHOT`: the Reference Library embedded viewer remains a preserved
  snapshot for browser parity.
- `LAYOUT_ONLY`: CSS, tabs, JavaScript controller, generated banners, and
  provenance blocks.

This classification is intentional and now declared in
`docs/index/manifest.json`; curated/static blocks must not be treated as
canonical runtime or release proof.

  generated blocks, and folded sections;

  sources;

  `docs/daee-epistemics-pipeline.html`;

  owners.

block lacks a provider, or if standalone generated pages lack generated
provenance.

and audit navigation still point to it. Deleting it would break navigation, and

`tools/build_docs_index.py`.

  pressure, loop-breaking, `R(H,Δ)`, or closure state; not used as proof by

  language saying Shannon/NLA/∇ must not measure truth or warrant.

No decorative `∇` prose, `∇`-as-`Δ` replacement, or `AⁿB` notation was found in
the generator-owned source.

## Remaining Source-Coupling Risks

- Architecture and Theory remain curated summaries. They are source-coupled by
  manifest owner paths and freshness digest, but not semantically regenerated
  from owner prose.
- Reference Library and embedded viewer snapshots remain static snapshots for
  parity. They can still become stale while the generator remains fresh.
- The standalone pipeline page is generated but still template-driven, not
  synthesized directly from `framework-pipeline.yaml`.
- The current release gate blocks silent rot through manifest classifications,
  generated banners, freshness checks, tab checks, and module catalogue parity,
  but it does not yet convert every visible explanatory paragraph into owner
  derived data.
