## Capture Transport

Preferred local capture transport is the packaged skill's file-retained syntax, run from an
installed or extracted final package context:

```text
/daee-epistemics < tests\smokes\current-release\v0.4.2.0\CR-01\input.md > tests\smokes\current-release\v0.4.2.0\CR-01\output.md
```

Repeat for `CR-02` and `CR-03`. The runtime context must be the final package
`build\daee-epistemics-v0.4.2.0.skill` or an extraction of that package, not loose
`atomics\skill\**` source. The resulting `output.md` files are raw local captures and remain
ignored/uncommitted.

The required inputs invoke `release-smoke witness capture mode`. This mode keeps the governed
answer but requires literal witness surfaces for local release-gate capture: `∇ route`, target
explicit `Field diagnostics:`, `LoopBreak:`, `R(H,Delta)`, `## Closure/Reconstruction Witness`,
`𝒞(Ψᴺ)`, `T_lang: Ψᴺ ⇢ Ψᴵ`, `## Restorative Response`, and `## Closing Formulation`.
These markers are evidence surfaces only; they are not competence proof, truth-meter proof, or
guaranteed uptake.

## Verdict Rules

`pending-live-output` means no real output has been captured yet. It is not PASS or PARTIAL
evidence.

`PASS` means a real package-bound output exists locally, the output is direct-copied, provenance
matches the package above, `ir.json` exists, the smoke checker passes, and review agrees the output
actually executes the relevant burden rather than merely printing witness labels.

`FAIL` means a real output exists but fails structure, provenance, witness, route, state-change,
closure, or review criteria. Keep the local output and record the failure honestly.

Witness markers are not competence proof. `nabla route`, `Delta`, `R(H,Delta)`, closure, and
`T_lang` are evidence surfaces only; the reviewer must still judge route correctness, local owner
execution, held-set reread, closure discipline, and restorative usefulness.
