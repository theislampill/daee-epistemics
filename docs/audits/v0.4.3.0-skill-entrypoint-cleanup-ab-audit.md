## PACK-SPEC checker scope

`tools/check_spec_authoring_pack.py` now checks:

- governance files: `AGENTS.md`, `docs/spec-authoring-pack.md`, and
  `docs/governance/operating-discipline.md`;
- contract owner pointers: diagnostic render contract, output release, diagnostic IR, and
  recursive-state transitions;
- ambiguous requirement phrases only in an allowlist of 11 spec-like files.

Noise controls:

- ordinary theory prose and case-library material are excluded;
- fenced examples are skipped;
- PACK-SPEC teaching lines such as counterexamples and "why it fails" explanations are skipped;
- the phrase list is intentionally narrow (`good enough`, `best effort`, `probably should`, and
  similar high-risk vague requirement phrases), not a global lowercase `should` linter.

## Hansei / 5 Whys

Gap: first Smoke F run allowed a hard-compound output to simplify closure/coupling notation.

Cause: the shrink was safe for routing and field banner behavior, but the local smoke validator did
not check ordinary hard-compound notation placeholders tightly enough.

Countermeasure: add a small root notation-preservation guard and extend
`tools/check_skill_ab_smoke_outputs.py` to reject ordinary output containing `ΨN`, `ΨI`, or
question-mark notation placeholders in closure/coupling surfaces.

Follow-up evidence: regenerated runtime, reran Smoke F, and reran the validator; latest F passed.

5 Whys summary: the symptom was simplified notation; the model allowed simplification because the
always-loaded root only named the closure symbols generally; the checker missed it because it
looked mostly for first-line and witness surfaces; the durable fix is a small notation guard plus
validator coverage at the smoke evidence boundary.
