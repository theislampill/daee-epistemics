## Goal

Add a docs-only Output Collapse Grapher so a reviewer can paste a daee-epistemics output, optionally paste `field_witness` JSON, and inspect whether the visible output is graphable and reconstructible from input through burdens, submoves, `Land(ⁿB)`, `R(H,Δ)`, `MRP(ⁿB)`, graph/field-witness deltas, route, closure, and restoration aim.

## UI / docs integration

The docs index exposes an `Output Grapher` tab with:

- daee-output paste area;
- optional `field_witness` JSON paste area;
- Parse / Graph action;
- summary, validation, graph, legend, and node-inspector panels;
- Export PNG, Export SVG, Export JSON, and optional lossy Export Mermaid.

The primary renderer is a local inline SVG/HTML renderer. Mermaid is export-only and includes an ELK renderer hint; it is not required for rendering or validation.

## Parser behavior

The parser extracts governed-output structure from visible text:

- first-visible governed execution and Layer A markers;
- initial burden inventory;
- burden nodes and generated-burden markers;
- submove nodes with owner/TTP labels;
- `Land(ⁿB)` / `HOLD(ⁿB)`;
- `R(H,Δ)`;
- `MRP(ⁿB)` resultants;
- route records;
- dependency graph edges;
- terminal states;
- closure/restoration indicators;
- optional `field_witness` node/edge comparison.

Canonical public notation is preferred. Legacy aliases such as `B1_1 [FPD]`, `Land(B1)`, `R(H,Delta)`, and `B1 -> B2` are parsed with warnings so older accepted outputs remain inspectable.

## Graph model

The default view is a vertical Rebuttal Story View, not a giant global DAG. It uses:

- top summary cards for final answer, rejected claim, diagnosis, failure points, and technical status;
- one burden-cycle card per failure point;
- nested submove/TTP-answer moves inside the correct burden card;
- local panels for what landed, what remained, follow-up pressure, and route/closure;
- a final Restoration Summary with plain-language synthesis only;
- final `Restorative Response` and `Closing Formulation` cards sourced from the visible output body when those sections are present;
- a bottom `Formal Case Fill` appendix for formal notation, terminal states, MRP ledger, closure/collapse proof, language boundary, and field-witness fill.

The readable infographic body is grounded in the visible skill output text. `field_witness` is secondary: it supports structure, graph relations, terminal states, and validation, but it does not replace the output text as the source of the visible rebuttal body.

The parser now splits pasted outputs into source zones before building cards:

- `body_prose`: main visible answer before closure/reconstruction witness;
- `closure_witness`: terminal graph/coverage proof block;
- `field_witness`: optional sidecar JSON pasted separately;
- `restorative_response` / closing formulation when present anywhere in the visible output before a `field_witness` sidecar.

The public body uses `body_prose` first for claim, burden, submove, landing, reread, MRP, and restoration text. Closure witness / `field_witness` data is used for graph edges, terminal states, route/resultant types, coverage, mismatch detection, and the bottom Formal Case Fill appendix.

Anti-DRY correction: the grapher is treated as a parser, normalizer, formatter, and visualizer, not as a new commentary layer. It no longer adds synthetic case summaries such as "a theological defense that mixes..." or generated reliance essays. Main cards preserve visible-output substance; terse machine labels may be lightly normalized, while raw taxonomy stays in the muted technical line.

Typography and source-shaping corrections:

- failure-point inventories render as vertical lists rather than dense paragraphs;
- diagnosis and claim cards use separated list items where the source contains multiple clauses;
- burden cards keep answer moves as separate stacked items;
- `Land(ⁿB)`, `R(H,Δ)`, `MRP(ⁿB)`, route, and restoration panels expand to content height;
- readable prose appears first, with technical notation reserved for the bottom formal appendix or inspector;
- giant oval/pill headers and floating oval labels are not used in the story view.
- internal taxonomy (`field`, `case`, `claim pattern`, `pattern profile`) is demoted to a muted technical line; the main diagnosis card explains the reply in public-facing prose first.
- exported Rebuttal Story PNGs default to a wide desktop/poster layout with size modes rather than a narrow compact capture.
- a compact `How to read this` help control sits in the top UI, collapsed by default, so the main map flow is not interrupted by a manual-style guide card.

The technical DAG remains available as an alternate view. MRP is rendered as edge/provenance/routing machinery, not as a separate burden namespace. Generated burdens are normal burden nodes marked by provenance, e.g. `³B [generated-by: MRP(²B)]`.

## field_witness comparison

When sidecar JSON is pasted, the parser compares visible burden nodes and graph edges with `field_witness` nodes/edges and reports mismatches. The checker includes a valid sidecar fixture for simple closure.

## Validation rules

Hard errors cover missing terminal states under complete closure, unknown graph nodes, MRP labels without resultants/routes, STOP-before-continuation, unbacked MRP-governed graph edges, and closure contradictions around non-neutral divergence/curl.

Warnings cover legacy aliases, subscript burden notation, missing visible submoves under landed burdens, and visible/sidecar mismatches.

## Checker

`tools/check_output_grapher.py` verifies:

- Output Grapher tab/source integration;
- no CDN/network dependency;
- primary inline SVG renderer;
- Export PNG/SVG/JSON buttons and optional Mermaid export;
- synthetic fixture pass/fail/warn behavior;
- exportable graph HTML/SVG generation;
- real skill-output parsing through `--skill-output` and optional `--expect-reconstructible`.

`tools/check_output_grapher_layout.py` verifies the layout source owners, comfortable default, semantic legend labels, non-compact story renderer, and no content-bearing CSS rules that would clip burden/status/restoration cards.

The parser now splits pasted output into visible body prose and closure/field-witness proof zones before rendering. Public infographic copy is resolved from the visible body first: burden headings, submove Target/Operation/Result/Contribution prose, `Land(...)`, `R(H,Delta)`, and Mid-Reread Pressure lines. Closure witness / `field_witness` data remains secondary and supplies structure, graph edges, terminal states, route/resultant type, and validation. Public labels normalize legacy `B1`, `B1_1`, `B1 -> B2`, `Land(B1)`, and `MRP(B1)` into canonical display forms such as `¹B`, `¹B₁`, `¹B → ²B`, `Land(¹B)`, and `MRP(¹B)`.

Follow-up route/submove correction: burden cards no longer repeat large scaffold chips such as "Problem / Failure shown / Next issue" on every card. Route panels no longer display an empty `RECURSE` restatement; they identify the next activated burden, explain why closure is withheld, and distinguish ordinary remaining-burden activation from MRP-generated pressure where available. Submove cards now render body-derived `Target`, `What it does`, `Result`, and `Contribution` text when the visible output provides those lines.

Final prose coverage correction: the renderer now detects visible-output `Restorative Response` and `Closing Formulation` sections and renders them as distinct final body-prose cards after the plain Restoration Summary. They are not synthesized from `field_witness`, and the export coverage report fails if those final sections disappear from the rendered/exported map.

Panel badge/layout correction: panel metadata badges such as `Land(¹B)`, `R(H,Δ)`, `MRP(¹B)`, and `STOP` / `RECURSE` now sit in the top-right of a measured header row. The panel title remains on the left, body content starts below a fixed header gap, and route rows use the full prose width instead of reserving a left badge lane.

Final vertical-fit correction: the story renderer trims trailing gaps after the last rendered content block and uses smaller explicit bottom padding for story panels, route rows, final prose cards, and submove cards. This preserves the current typography and full output-derived prose while reducing cumulative export height.

Formal-layer correction: the technical proof strip was removed from the Restoration Summary and moved to a distinct bottom `Formal Case Fill` appendix after the Closing Formulation. Land/Reread panels now rely on their top-right technical badges instead of duplicating `Technical: Land(...)` or `Technical: R(H,Δ)` lines in the body.
