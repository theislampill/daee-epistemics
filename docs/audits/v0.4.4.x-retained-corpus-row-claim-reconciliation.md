# v0.4.4.x Retained-Corpus Row-Claim Reconciliation

Status: ACTIVE CURRENT TRUTH (claim-boundary reconciliation). This note makes
retained proof-corpus claims truthful under the current validator set. It does
not modify any retained output or proof sidecar, does not weaken any
validator, does not promote retained proof, does not run model smokes, and
does not reopen the published v0.4.4.0 boundary.

## Trigger

The Wave 1 structural-integrity lane ran the full row-validator family over
the 24-case sidecar-backed corpus with corpus-wide globs and found 16 of 24
cases failing at least one current validator (graph-completeness 10,
mid-reread-pressure 5, field-witness convergence 2, manual render 2, MRP
generated-burden 1, ACT surface syntax 1, public burden grouping 1), while CI
stayed green because those validators ran only in embedded/fixture mode.

## Root finding: validation-scope aliasing, not stale claims

Claims-scoped replay (graph `--json` per-condition evaluation; bound-subset
checker runs) proves:

- All 14 B.1-claiming cases pass the full graph-completeness capstone.
- Every C-row claimant passes every graph condition key its rows actually
  claim (C.1 primary_root_verification, C.2 typed_escape_route_accounting,
  C.3 formalism_emergent_escape_route_closure, C.6 two_track_mrp_closure,
  C.7 divergence_curl_generated_burden_rules, C.8
  no_new_resultant_terminal_proof).
- D.2 claimants pass manual render contract (8/8); D.3 claimants pass
  concealment mode (5/5); C.7 claimants pass MRP generated-burden (14/14);
  B.5 claimants pass NLA decode; T_lang claimants pass response closure; the
  A.9 anchor passes owner-activation ordering with plan.

Every Wave 1 corpus-glob failure therefore lands on a surface the failing
case never claimed, with exactly one narrowing exception (source-order-tlang
C.4, below). The corpus-glob invocation conflated two hidden proof roles —
"claimed-row evidence" and "incidental property of an output that happens to
be in the corpus" — one surface invocation carrying two latent states: an
OSM-style alias in the validation infrastructure itself.

Timeline evidence for the drift context: failing chat-era cases were promoted
2026-05-31 (`956ac9f`, `f75eca6`, `2c05a18`) and 2026-06-03 (`ab1e893`); the
contract hardening landed 2026-06-04..06 (`76ca709` despecialize proof gates,
`c760206`/`7df6fca` SOURCE typed transitions, `faa688d`/`161cb65` act delta
carrier split); Gate88 cases were promoted 2026-06-07 (`651b5b9`) under the
new rules. The open-work ledger records the 18-case corpus passing all graph
keys on 2026-05-31, proving checker evolution rather than artifact change.

## Countermeasure (executable, source-owned)

1. `coverage_targets[*].validator_binding` added to the canonical manifest:
   every coverage target now names the validator evidence that guards its row
   (`graph-keys`, `outputs-checker`, `corpus-integrity`, or
   `documented-evidence`).
2. Five new coverage targets bind previously unbound claimed rows: A.9
   (owner-activation ordering anchor), C.1, C.2, C.3, C.8 (graph condition
   keys). Every claimed row in the corpus now has a bound coverage target.
3. New driver `tools/check_retained_row_claims.py` replays exactly the
   claimed scope (one graph `--json` run evaluated per bound key per claiming
   case; bound checkers invoked unchanged over exactly the claiming cases),
   enforces binding presence and full row coverage, and is wired into CI with
   its self-test. Validators are not modified.
4. `tools/check_retained_proof_corpus.py` gains additive schema support only:
   optional per-case `contract_notes` and per-target `validator_binding`
   validation. No existing check is relaxed.
5. `proof_boundary` now states that row claims are coverage-target-scoped and
   that corpus-glob validator runs outside a case's claimed rows are advisory
   context recorded in `contract_notes`, not claim failures.
