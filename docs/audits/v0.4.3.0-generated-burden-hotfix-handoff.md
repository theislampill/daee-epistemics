# v0.4.3.0 Generated-Burden Hotfix Handoff

## Status

Tracked handoff mirror for the ignored root `HANDOFF.md`.

## Scope

This hotfix distinguishes ordinary held-burden activation from MRP-generated burden
instantiation and normalizes public burden notation toward canonical `ⁿB`, `ⁿBᵢ[OPᵢ]`,
`MRP(ⁿB)`, and `ⁿB → ⁿ⁺¹B` forms.

## Evidence Boundary

- Deterministic fixture/checker proof: yes.
- Generated runtime/docs freshness: yes, after rebuild.
- Fresh hosted Smoke 7 model-output proof: not run in this pass.
- Raw smoke outputs: local evidence only; not committed and not release assets.

## Route Result Types

- `held_burden_activation`: MRP authorizes movement to an already-inventoried held burden.
- `generated_burden_instantiation`: `MRP(ⁿB)` surfaces a new post-landing resultant burden and
  instantiates it as a normal burden node.
- `no_new_resultant`: MRP finds no additional resultant burden beyond ordinary routing.
- `loopbreak`: MRP detects churn/curl and blocks proof-stacking.
- `hold_partial`: MRP detects real unresolved pressure and prevents false closure.

## Release Caveat

The v0.4.3.0 release body must say that generated-burden behavior is deterministic
fixture/checker proven in this hotfix. It must not claim a fresh hosted Smoke 7 behavioral proof.
