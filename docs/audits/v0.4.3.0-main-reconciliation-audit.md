## Subagent findings

### Runtime invariant auditor

Runtime owners in the repaired release branch and the `v0.4.3.0` tag matched,
while `origin/main` was missing the repaired MRP and notation behavior. The
auditor recommended taking release-source runtime owners as authoritative and
preserving only compatible main CI/provenance improvements.

### Checker/fixture auditor

`origin/main` was missing the focused generated-burden, route/curl, and
Trinitarian hotfix checkers and fixtures. The auditor recommended bringing the
release checkers/fixtures forward and wiring `check_mrp_generated_burden.py`
into CI/release validation.

### Generated/docs/provenance auditor

Generated docs conflicts should be rebuilt, not hand-resolved. The live GitHub
Release asset remains the release source of truth:

  `A1FBFE6C507923416FC255E0140E5ECDD30BE1E055DC9310F02D16189212269C`
- skill asset size: `625827`
- provenance asset digest:
  `sha256:7dfe9d4a76177d965ef8c41d0554e39b0974519815d4ad01b9baf8ad6cb17fed`
- released source commit: `3fbee9d5a6b233ebcfec7ffc5a69ed044365b331`

### Adversarial merge reviewer

Blindly merging the diagnostic branch into `main` was unsafe because generated
docs and rollback/provenance guardrails diverged. The recommended strategy was
a semantic reconciliation from `origin/main`, restoring released runtime and
checker invariants while regenerating docs and preserving rollback evidence as
historical context.

must not move the tag or update the release asset.
