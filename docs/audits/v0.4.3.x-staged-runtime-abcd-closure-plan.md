# v0.4.3.x Staged Runtime A/B/C/D Closure Plan

Status: `CLOSURE_PLAN_ONLY; NO_BROAD_ROW_CLOSURE_CLAIM`.

Date: 2026-06-02

This plan explains how staged execution can later close remaining A/B/C/D row
families. It is not a completion claim. One staged smoke, even if it passes,
proves one-case staged execution only.

## Closure Rule

A row can move from partial to closed only when a staged row-family campaign is
owner-selected, validator-clean, retained or otherwise proof-owned, and mapped
back to the canonical open-work ledger and orchestrator. Failed staged runs are
negative evidence and do not close rows.

## Current Closure State

The retained replay bridge creates the replay target shape. The staged
current-skill harness prototype creates the first model-stage runner. The first
run localized a Stage 03 route-target shape mismatch; the follow-up repair now
has one Stage-03-scoped current-skill PASS with canonical `route_targets` and
optional `route_target_details`.

This does not close broad A/B/C/D rows because no final governed `output.md`,
proof sidecars, retained-corpus promotion, or row-family campaign was produced.

## Recommended Order

1. Treat Stage 03 routing-shape repair as complete for one scoped retry.
2. If continuing staged execution, choose the next stage or single row family
   deliberately; do not rerun the whole staged system as a broad smoke.
3. If one-case proof-surface pass is later achieved, choose a single row family,
   probably B.1/B.2 first, and design a small staged proof matrix before
   running it.
4. Only after retained proof evidence accumulates should row-family closure be
   considered.
