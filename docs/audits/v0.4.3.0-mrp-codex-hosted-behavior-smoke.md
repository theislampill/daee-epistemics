## Proof that v0.4.2.0 lacks MRP

The proof is narrow. v0.4.2.0 can be strong and governed: it has box-art, Layer A/B burden
progression, submoves, `Land(Bn)`, `R(H,Delta)`, and closure graph behavior. It does not expose
MRP as a named TTP, does not render MRP pressure slots, does not record `MRP resultant`, and
does not explicitly route through MRP before closure or next-burden release. Searches for MRP
markers in the baseline skill and hard comparator output returned no hits.

## Proof that v0.4.3.0 uses MRP

Repair14 proves MRP behavior because the output is reconstructible as:

Input -> burden nodes -> owner-bearing submoves -> `Land(Bn)` -> `R(H,Delta)` ->
MRP pressure activations -> `MRP resultant` -> graph/route delta -> next burden or STOP ->
closure/restoration.

Operational markers in repair14:

- first-visible governed execution banner;
- Layer A compact diagnostic header with initial burden set and dependency graph;
- 6 released burden cycles and 48 owner-bearing submove activations;
- 6 MRP invocations;
- graph deltas from B1 through B6;
- final `MRP resultants` ledger;
- closure witness before restorative response;
- `T_lang` non-guaranteed uptake boundary.
