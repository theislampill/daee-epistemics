# v0.4.3.0 Retained Smoke Sidecar Convention

Status: active IMPLEMENTAUDIT process guidance.

This document standardizes the schema-light B.2/B.4 evidence shape for retained
governed smoke artifacts. It is not release notes, not runtime source, and not a
replacement for the active proof ledger:
`docs/audits/v0.4.3.0-implementaudit-orchestrator.md`.

## Purpose

When a governed smoke is promoted as B.1/B.2/B.3/B.4 proof evidence, retain the
artifacts needed for checker-owned proof:

- governed Markdown output;
- raw D0 input sidecar;
- checker-owned collapse certificate JSON;
- certificate-backed Output Grapher HTML, when graph proof is claimed;
- repository-normalized text hashes for all retained artifacts;
- command evidence recorded in the orchestrator.

Graphify, browser display, public graph reconstruction, model-authored proof
booleans, and inline certificate prose are navigation or display only. They are
not proof without the Python checker stack.

## Required Sidecar Set

For each retained governed smoke promoted as collapse/certificate evidence,
preserve:

```text
<case>.raw-input.txt
<case>-runN.md
<case>-runN.collapse-certificate.json
grapher/<case>-runN-certificate.html
<case>-runN.hashes.json
<case>-runN.exit.txt
```

Names may vary by lane, but the role of each artifact must be unambiguous in
the orchestrator.

## Required Commands

Run the proof-producing/checking commands from the current worktree:

```powershell
python tools\check_graph_completeness.py --outputs <output.md> --certificate --input <raw-input.txt> > <collapse-certificate.json>
python tools\check_collapse_certificate_schema.py --certificates <collapse-certificate.json>
python tools\check_output_grapher.py --skill-output <output.md> --expect-reconstructible --fail-on-warnings --input <raw-input.txt> --collapse-certificate <collapse-certificate.json> --out <grapher.html>
```

Use `tools\build_retained_proof_sidecars.py` to generate checker-owned
sidecars from the raw input and governed output before promotion:

```powershell
python tools\build_retained_proof_sidecars.py --input <raw-input.txt> --output <output.md> --out-dir <sidecar-dir> --prefix <case-run>
```

The helper runs graph-completeness certificate emission, collapse-certificate
schema validation, certificate-backed warning-clean Output Grapher generation,
and repository-normalized hash writing. It does not replace row-specific
validators or orchestrator evidence.

For new current-skill smokes that already have a raw D0 input sidecar, the
standard wrapper can invoke the same builder immediately after a successful
Codex run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run_current_skill_smoke.ps1 -Root (Get-Location).Path -CaseName <case> -PromptPath <prompt.txt> -RunDir <run-dir> -OutputBaseName <run-name> -BuildProofSidecars -RawInputPath <raw-input.txt>
```

This writes sidecars under `<run-dir>\proof-sidecars\` by default and records
their paths/hashes in the smoke hash JSON. It is still a harness convenience,
not proof by itself; row-specific validators and orchestrator evidence remain
required. CI runs the wrapper's no-model proof-sidecar self-test, which builds
sidecars for a retained A9 case in a temporary directory and verifies the
wrapper `proof_sidecars` hash-record shape:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run_current_skill_smoke.ps1 -Root (Get-Location).Path -ProofSidecarSelfTest
```

The self-test writes a full checkout-local smoke hash record under ignored
`.daee\validation`, validates it with `tools\check_smoke_artifacts.py
--hash-record`, and sends the same record through
`tools\promote_retained_proof_case.py --source-only --hash-record`. This proves
the wrapper-emitted record can feed the promotion helper's source-artifact gate
without writing or comparing a retained manifest.

`tools\check_smoke_artifacts.py` also validates any `proof_sidecars` records
found in `*.hashes.json`: required sidecar entries must be present, paths must
exist, SHA256 values must be well formed, and recorded hashes must match the
referenced files. The checker has committed positive/negative hash-record
fixtures under `tests\smoke-artifacts\proof-sidecars\` and may validate a
specific current-smoke hash record directly:

```powershell
python tools\check_smoke_artifacts.py --hash-record <run>.hashes.json
```

When a lane expects checker-owned proof sidecars rather than treating them as an
optional smoke-record extension, use strict mode:

```powershell
python tools\check_smoke_artifacts.py --require-proof-sidecars --hash-record <run>.hashes.json
```

The current-skill wrapper self-test uses this strict mode. Its generated
`*.hashes.json` files are written as UTF-8 without BOM so the Python checker
stack reads them consistently under Windows PowerShell and PowerShell 7. Normal
smoke hash records without `proof_sidecars` remain valid unless a proof-sidecar
lane explicitly opts into `--require-proof-sidecars`.

Use `tools\promote_retained_proof_case.py` and
`tools\check_retained_proof_corpus.py` for retained-manifest hashes. Those
tools normalize CRLF and bare CR to LF for text artifacts, so the committed
manifest is stable across Windows and GitHub Ubuntu checkouts. `Get-FileHash`
may still be recorded as a local raw-file diagnostic, but it is not the
retained-manifest hash authority.

If the artifact is part of a broader retained corpus, also run the relevant
row-specific validators: ACT surface syntax, strict MRP, manual render, live
witness, mid-reread, formal reread, field-witness convergence, owner ordering,
NLA decode, T_lang closure, concealment mode, and graph completeness as
applicable.

For the committed schema-light retained proof corpus, also run:

```powershell
python tools\check_retained_proof_corpus.py
```

That checker binds the retained raw input, governed output, checker-owned
collapse certificate, warning-clean certificate-backed Grapher HTML, and
repository-normalized text hashes. It is a corpus-integrity gate only; it does
not replace the row-specific validators above. The corpus and hard-smoke
manifest checkers include a built-in hash-portability self-test so LF/CRLF text
normalization remains stable while binary-like content remains byte-sensitive.

The canonical retained sidecar manifest also carries `coverage_targets` for
row-family accounting. The corpus checker verifies that each target names real
retained cases and that those cases carry the target row IDs. This prevents the
B.1/B.2/B.3/B.4/B.5/T_lang core proof rows and the C.5/C.6/C.7/D.2/D.3
retained matrices from drifting silently, but it remains accounting metadata:
row-specific validators and orchestrator evidence still prove the behavior.

For the specialized B.5.4 proof-mode/full-IR adoption target, a retained case
may also carry a checker-owned projection sidecar:

```json
"b5_full_ir_projection_sidecar": {
  "schema": "b5-retained-proof-mode-full-ir-sidecar-v1",
  "path": "cases/<case-id>/b5-full-ir-projection-sidecar.json",
  "sha256": "<repository-normalized SHA256>",
  "builder": "tools/build_b5_full_ir_projection_sidecar.py"
}
```

Build that sidecar only from an already validator-clean retained governed
artifact:

```powershell
python tools\build_b5_full_ir_projection_sidecar.py --input <raw-input.txt> --output <output.md> --collapse-certificate <collapse-certificate.json> --grapher-html <grapher.html> --out <b5-full-ir-projection-sidecar.json>
```

The builder and retained-corpus checker derive and validate the projection from
visible ACT rows, parser-stable `field_witness`, NAR,
`coverage_proof.dependency_graph`, terminal states, formal reread evidence,
the checker-owned collapse certificate, and warning-clean Grapher sidecar. They
must not parse arbitrary prose into IR and must not modify the governed output.
The sidecar proves only checker-owned retained projection adoption for the
listed case; it is not runtime/default emission proof, not broad corpus
adoption, not model-smoke proof, and not guaranteed `T_lang` uptake.

To reduce manual manifest drift when promoting a governed smoke, use the
promotion helper in check mode first:

```powershell
python tools\promote_retained_proof_case.py --check --case-id <case-id> --rows <row ids> --generated-skill-sha <sha> --origin <output origin> --input <raw-input.txt> --output <output.md> --collapse-certificate <collapse-certificate.json> --grapher-html <grapher.html>
```

When the governed smoke was run through `tools\run_current_skill_smoke.ps1`
with `-BuildProofSidecars`, prefer the hash-record intake so the four source
artifact paths come from the checker-validated smoke record:

```powershell
python tools\promote_retained_proof_case.py --check --case-id <case-id> --rows <row ids> --origin <output origin> --hash-record <run>.hashes.json
```

For wrapper/harness smoke validation that should not compare or write a retained
manifest, use the source-artifact gate:

```powershell
python tools\promote_retained_proof_case.py --source-only --hash-record <run>.hashes.json
```

Without `--check`, the helper copies the four canonical retained artifacts into
`tests/retained-proof-corpus/v0.4.3.0-schema-light/valid/sidecar-backed/cases/<case-id>/`
and appends the manifest entry with computed hashes. Use `--replace` only when
intentionally refreshing an existing retained case. The helper validates the
certificate schema, raw-input fingerprint, positive collapse flags, warning-
clean Grapher HTML, smoke hash-record paths/hashes when `--hash-record` is
used, and retained-manifest integrity, but it still does not replace row-
specific validators or orchestrator evidence. CI runs
`python tools\promote_retained_proof_case.py --self-test` against the retained
A9 case using checkout-local synthesized hash records and a stale-output canary.
Do not commit promotion-specific raw hash records for retained text artifacts:
their raw byte hashes can differ across Windows and LF checkouts. The committed
proof-sidecar hash fixtures under `tests\smoke-artifacts\proof-sidecars\`
remain for the generic checker shape; promotion-helper coverage lives in the
helper self-test.

## Classification

Use these classifications in the orchestrator:

| Classification | Meaning |
|---|---|
| `SIDECAR_BACKED_PROOF` | Output has raw input, checker-owned certificate, schema validation, and certificate-backed Grapher proof when graph proof is claimed. |
| `ROW_SCOPED_ONLY` | Artifact is valid for a narrower row, such as A.12 reproducibility, and is not B.2/B.4 sidecar proof. |
| `MANIFEST_BOUND` | Artifact is governed by a hard-smoke manifest or release manifest path rather than normal retained-smoke sidecars. |
| `MISSING_SIDECAR` | Artifact is otherwise promising but lacks a raw input, certificate, Grapher proof, or hash needed for B.2/B.4 evidence. |
| `REJECTED_AS_PROOF` | Artifact failed a validator or relies on model-authored/browser/display proof only. |

## Boundaries

- Do not require ordinary runtime output to print inline collapse certificates.
- Do not treat `field_witness.provenance.input_hash` as authoritative; it is a
  cross-check when present.
- Do not treat browser Output Grapher display as proof; Python
  certificate-backed agreement is the proof authority.
- Do not package, tag, upload, publish, or edit release notes from this
  convention.
- Do not use this convention to start A.13 hard register schema migration.
- Do not use this convention to close D.8 subagent cleanup.

## Recording Rule

Every promoted retained smoke sidecar proof must record, in the orchestrator:

- artifact paths;
- SHA256 hashes;
- generated skill SHA when available;
- validator commands and PASS/expected-FAIL summaries;
- rows advanced;
- rows that remain partial;
- release/provenance boundary.
