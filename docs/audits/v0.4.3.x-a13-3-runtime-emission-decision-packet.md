## Decision Question

Should runtime/default governed outputs emit hard-register fields?

Possible answer:

- **Yes, but only as version-gated machine evidence first.** Emit hard-register
  state through `field_witness.canonical_ir_projection` under
  `diagnostic_ir_schema_version = "0.4.3-hard-registers-v1"` when the runtime
  can prove the five-register set from the same evidence that currently feeds
  NAR, register deltas, and diagnostic completeness.
- **Not yet as public prose.** Public prose should continue to expose the
  noetic work through burdens, owner/TTP operations, state re-read, and
  restorative closure. Hard-register state is a machine-facing proof surface.
- **Not yet always-on for every output.** Always-on default emission should wait
  until retained-output readability, checker compatibility, and package/release
  boundaries are proven.

## Always-On, Opt-In, Or Version-Gated?

Recommended first policy:

1. Version-gated: every hard-register emission must carry
   `diagnostic_ir_schema_version = "0.4.3-hard-registers-v1"`.
2. Opt-in / selected-surface first: emit in focused governed outputs or retained
   proof cases selected for A.13.3 validation.
3. Backward-compatible: schema-light outputs remain valid without the marker.
4. Checker-owned: `check_ir_instance_integrity.py`,
   `check_register_formalism_bridge.py`, and
   `check_nla_decode_semantic_faithfulness.py` must reject mismatches.
5. No uptake claim: hard-register fields describe runtime-side diagnostic state,
   not interlocutor restoration or `T_lang` success.

Do not choose always-on default emission as the first implementation slice
unless the owner accepts the output-size/readability and retained-corpus churn
risk explicitly.

## Risks And Stop Conditions

Stop if:

- schema-light retained outputs become invalid without an explicit marker;
- hard-register projection is described as full IR decode;
- `sigma` is added to the hard-register object;
- public prose becomes bloated by raw machine fields;
- field_witness/NAR/register-delta/diagnostic-completeness agreement weakens;
- model-smoke, package, tag, upload, GitHub Release, release asset, or
  provenance work becomes necessary;
- the patch requires default always-on hard-register emission before the
  owner explicitly accepts that risk.
