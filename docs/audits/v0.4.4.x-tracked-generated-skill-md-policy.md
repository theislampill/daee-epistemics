# v0.4.4.x Tracked Generated `skill/SKILL.md` Policy and CI Staleness Gate

Status: ACTIVE CURRENT TRUTH (governance/decision note). This note records a
source/runtime boundary decision and its poka-yoke. It is not release proof,
not a package change, and does not reopen the published v0.4.4.0 boundary.

## Context

- `skill/**` is generated compiled runtime output and is ignored via
  `.gitignore` (`/skill/`), with one deliberate exception: `skill/SKILL.md`
  has been force-tracked since the v0.4.3.0 corrected-goal closure commit
  `9a57961395643a1b56a1c39fcb8026d17d1ca6d7`. It is the exact-file "current
  skill" surface consumed by the staged runner and hashed into smoke
  provenance (generated-skill SHAs in audit ledgers).
- Before this note, `AGENTS.md` and `docs/release-artifacts.md` still
  described `skill/**` as entirely untracked, and the historical poka-yoke
  `git ls-files skill == 0` no longer matched the tree.
- CI rebuilt `skill/` before running
  `tools/check_compiled_runtime_freshness.py`, so a stale *committed*
  `skill/SKILL.md` could never fail CI: the rebuild overwrote the checkout
  before any comparison. Only `framework-pipeline.md` had a commit-state
  `git diff --exit-code` gate. The v0.4.1.0 history-regression archaeology
  audit records "generated runtime tracking/source drift" as a recurring
  historical failure class for exactly this surface.

## Decision

1. `skill/SKILL.md` remains force-tracked generated runtime. Other `skill/**`
   paths remain ignored/generated. Never hand-edit the tracked copy; edit
   `atomics/skill/**` and rebuild.
2. The repository invariant is: `git ls-files skill` returns exactly
   `skill/SKILL.md`.
3. CI enforces commit-state freshness with a post-build gate in
   `.github/workflows/ci.yml`:

   ```bash
   git diff --exit-code -- skill/SKILL.md
   ```

   placed immediately after `tools/check_compiled_runtime_freshness.py`. A
   push whose committed `skill/SKILL.md` does not byte-match a rebuild from
   the same commit's atomics fails CI.
4. `AGENTS.md` (Repository Rule, poka-yoke list, formalism layout note,
   package-shape rule) and the `docs/release-artifacts.md` preamble are
   reconciled to this wording. Historical release-table rows keep their
   original wording as historical facts and are not retroactively rewritten.

## Evidence

- Boundary at decision time: `HEAD == origin/main ==`
  `bffcc27777718ce94953eef3a45b2b601e558e55`; CI run `27085312548` success;
  Pages run `27085312374` success.
- `git ls-files skill` returns exactly `skill/SKILL.md`.
- Local rebuild at this boundary (`build_framework_pipeline.py`,
  `build_compiled_runtime.py`) produced a byte-identical tracked
  `skill/SKILL.md` (`git diff --exit-code -- skill/SKILL.md` exit 0) and
  `check_compiled_runtime_freshness.py` PASS, so the gate lands green.
- Negative control: mutating the tracked copy makes the gate command fail;
  rebuilding restores byte identity and the gate passes.

## Consequences

- A maintainer who edits atomics and forgets to rebuild and commit the
  tracked runtime can no longer pass the `runtime-checks` job green; the
  checker exists and is accurate. Full branch-level enforcement still depends
  on GitHub branch protection or rulesets requiring that job before merge.
- Package payloads, release assets, tags, and provenance are unchanged by
  this note and gate.

## Rollback / defer

Remove the single `git diff --exit-code -- skill/SKILL.md` line from
`.github/workflows/ci.yml` and revert the wording edits. Untracking
`skill/SKILL.md` entirely is a separate owner decision and would need a
staged-runner/provenance migration plan first.
