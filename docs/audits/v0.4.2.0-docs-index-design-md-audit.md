# docs/index DESIGN.md Audit

## Verdict

DOCS/INDEX-SCOPED DESIGN.md ADOPTED; ROOT DESIGN.md DEFERRED

The Google DESIGN.md pattern is useful for this repository as a scoped docs/index design system: YAML front matter gives the generator exact token values, while Markdown prose records visual rationale and boundaries for maintainers and coding agents. A root repo-wide `DESIGN.md` is not warranted yet because the current need is the generated public docs/index visual system, not package/runtime semantics.

## Upstream applicability

Google's format combines machine-readable YAML design tokens with human-readable Markdown rationale. The relevant parts are tokenized colors, typography, spacing, rounded/radius values, component guidance, and lint/export ideas. The upstream format is still alpha, so this pass uses it conservatively and adds local repo checks instead of depending on an external CLI gate.

## Local source of truth

- Design source: `docs/index/DESIGN.md`.
- Runtime architecture source: `docs/index/runtime-architecture.json`.
- Generator: `tools/build_docs_index.py`.
- Checker/controller: `tools/check_docs_index_interactions.py`.

`docs/index.html` remains generated output and is not canonical.

## Token coverage

`docs/index/DESIGN.md` defines:

- `colors`: background/surface/text/border/focus, status colors, and five Architecture stage colors.
- `typography`: body, small, label, heading, monospace, and notation roles.
- `spacing`: base scale plus card, section, and carousel spacing.
- `radius` and `rounded`: chip, card, panel, and carousel shape tokens.
- `shadow`: card, active-card, and preview-card depth.
- `motion`: duration, easing, and reduced-motion policy.
- `components`: Architecture carousel, Architecture card, carousel preview, controls, pipeline rows, Theory notation, Owner/TTP map, and Reference Library.

## Generated from tokens

`tools/build_docs_index.py` parses `DESIGN.md` YAML front matter and emits CSS custom properties into `docs/index.html`, including compatibility variables used by the existing template. The Architecture stage colors, carousel dimensions, carousel motion, focus color, preview opacity, and preview heights now come from design tokens.

## Final visual consolidation

The DESIGN.md layer remains docs/index-scoped and does not own runtime semantics. Final local visual verification confirmed the token-backed Architecture carousel keeps one selected readable primary card, scaled side previews of the actual generated cards, no automatic rotation, reduced-motion handling, and mobile/print/no-JS fallbacks. Card-4 dense example rows, LoopBreak witness, and Decision grid containment are fixed in template/generator code rather than generated HTML. Theory card-to-notation active states use the same focus/active visual vocabulary without moving runtime meaning into DESIGN.md.

## Curated by design prose

The Markdown body is rationale and operating guidance. It does not own runtime theory, owner/TTP semantics, release evidence, or smoke proof. Colors distinguish stage identity but do not imply truth, warrant, competence, or uptake.

## Checks

`tools/check_docs_index_interactions.py` now verifies:

- `DESIGN.md` exists and parses as YAML front matter.
- Required token groups and stage colors exist.
- token references resolve.
- generated CSS custom properties are present.
- the carousel references design tokens.
- token-backed focus and reduced-motion styles exist.
- the manifest declares `docs/index/DESIGN.md` as the design source.
- the Architecture carousel remains selected-primary with scaled actual-card previews and no auto-rotation.
- Theory card-to-notation controls retain visible active state and keyboard-accessible notation chips.
- Architecture stage color CSS does not retain stale hardcoded RGB stage colors.
- key foreground/background token pairs pass a lightweight WCAG AA contrast sanity check.

Official Google `design.md` lint was attempted with `npx.cmd @google/design.md lint docs/index/DESIGN.md` but did not complete in the local environment before timeout. The local checker remains the active gate for this pass.

## Remaining caveats

Some older docs/index CSS still contains one-off literal layout and emphasis values. This pass intentionally tokenizes repeated system and component values instead of forcing a broad visual rewrite. Future hardening can migrate more legacy one-off values after visual QA, but runtime semantics must remain isolated from the design source. This is not a release/smoke proof and does not claim live-output behavior beyond the separate package-bound smoke gate.
