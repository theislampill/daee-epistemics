# v0.4.1.0 Docs Index Generator Parity Audit

Status: CURRENT-CANDIDATE

Scope: `docs/index.html` generator conversion and parity guard. This audit treats
`docs/index.html` as a generated public viewer, not as an independent owner.

## Generator Existence

No prior `docs/index.html` generator or `docs/index/` source tree existed. The
page was a hand-authored derived surface with inline CSS, inline data, inline
JavaScript, and no freshness check against owner files.

Bootstrap step: the repaired browser-working `docs/index.html` was mechanically
split into `docs/index/templates/index.html.tpl` plus four section fragments to
preserve current page parity before replacing stale hand-authored module rows
with owner-derived data.

## TTP / Module Parity

Owner source: `atomics/skill/references/diagnostics/module-catalogue.json`.

## Checker Coverage

`tools/check_docs_index_interactions.py` now verifies:

- generated-file banner;
- generation freshness via `python tools/build_docs_index.py --check`;
- every tab trigger points to an existing panel;
- every panel has a corresponding trigger;
- tab and panel IDs are unique;
- expected top-level tab labels exist;
- initial active/hidden state is coherent;
- hash/ARIA controller tokens are present;
- JavaScript syntax parses under Node when available;
- embedded module catalogue data exactly matches
  `atomics/skill/references/diagnostics/module-catalogue.json`.

## Remaining Risks

- The first generator pass intentionally preserves large bootstrap HTML
  fragments for visual and behavioral parity. Future cleanup can reduce source
  size, but that is not part of this release gate.
- The Reference Library remains a static embedded viewer snapshot. It is
  preserved for parity and should be made more owner-derived in a later, separate
  task if desired.
- Browser verification used localhost, not direct `file://`, due browser
  security policy.

## Source-Coupling Appendix

Follow-up coherence work is tracked in
`docs/audits/v0.4.1.0-docs-index-source-coupling-audit.md`.
The key result is that the generator is intentionally mixed:
`OWNER_DERIVED` for the live module-catalogue table,
`STRUCTURED_SOURCE_DERIVED` for generated shells and tab registry,
`CURATED_SUMMARY_WITH_OWNER_REFERENCES` for Architecture/Theory explanations,
and `STATIC_SNAPSHOT` for the preserved embedded reference viewer. That audit
also records that Pipeline is folded into Architecture, Case Library is folded
into Reference Library plus Owner/TTP catalogue rows, and the standalone
pipeline HTML page is now generated from `docs/index/templates/pipeline.html.tpl`.
