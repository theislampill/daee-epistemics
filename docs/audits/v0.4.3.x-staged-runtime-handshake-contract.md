# v0.4.3.x Staged Runtime Handshake Contract

Status: `NO_MODEL_FIXTURE_CONTRACT`.

This document defines the scratch-record contract for staged skill-as-code
execution. It is a harness/dev contract only. It does not run the runtime,
does not parse arbitrary prose into IR, does not claim model behavior, and
does not replace the full governed `output.md`.

## Minimum Stage Sequence

```text
stage-01-intake
stage-02-layer-a-diagnostic-ir
stage-03-routing-owner-gate
stage-04-burden-execution-act
stage-05-mrp-reread-terminal-state
stage-06-field-witness-nar
stage-07-release-output
stage-08-verifier-sidecars
```

Every stage must appear exactly once and in order.

## Required Handoffs

1. Intake -> Layer A

   - input digest / case id / source boundary is preserved;
   - no answer/release occurs yet.

2. Layer A -> Routing

   - burden floor exists;
   - selected or held N-frame exists;
   - live registers / diagnostic IR state exists;
   - unresolved or held state is explicit.

3. Routing -> Burden execution

   - owner/TTP route exists for each selected burden;
   - route is catalogue-backed or held with reason;
   - no owner activation occurs without eligibility.

4. Burden execution -> MRP

   - ACT rows exist;
   - body_ref exists;
   - ACT owner/operation/delta/Land fields are canonical or checker-normalizable;
   - Layer B body exists for each body_ref.

5. MRP -> Field witness

   - dependency graph edges are explicit;
   - terminal states are explicit;
   - no-new-resultant or HOLD/PARTIAL is explicitly accounted.

6. Field witness -> Release

   - owner_activations mirror ACT rows;
   - normalized_activation_record mirrors field_witness/ACT;
   - field_witness convergence passes or release is HOLD/PARTIAL.

7. Release -> Verifier sidecars

   - output.md exists as the governed answer where release is claimed;
   - graph/certificate/Grapher sidecars exist where claimed;
   - optional B.5.4.1 full-IR projection sidecar is built only from validated
     evidence.

## Checker Contract

`tools/check_staged_runtime_handshake.py` validates:

- record root is a JSON object;
- schema is `staged-runtime-handshake-v1`;
- required stage order is present exactly once and in order;
- no stage is skipped;
- every handoff references existing stages;
- required handoff checks are present;
- non-claims are present and true;
- output paths, when referenced, are relative and do not escape the repo root;
- artifact SHA256 fields are well formed;
- pass handoffs preserve required stage fields;
- held/partial stages prevent downstream complete-closure claims.

The first semantic checks are intentionally bounded:

- `burden_floor` in stage 02 must match `route_targets` in stage 03;
- `route_targets` in stage 03 must match `act_targets` in stage 04;
- `act_body_refs` in stage 04 must match `field_witness_body_refs` in stage 06;
- `nar_burdens` in stage 06 must include ACT burdens from stage 04;
- `terminal_states` in stage 05 must match `release_terminal_states` in stage 07;
- if stage 08 claims B.5.4.1 sidecar evidence, stage 07 must have output
  evidence and stages 05/06 must have terminal/NAR evidence.

If `stage-08-verifier-sidecars` claims B.5.4.1, it must reference:

- `tools/build_b5_full_ir_projection_sidecar.py`;
- sidecar schema `b5-retained-proof-mode-full-ir-sidecar-v1`;
- checker-owned final verifier role;
- non-claim that the sidecar does not prove fresh runtime/default emission.

## Fixture Roots

```text
tests/staged-runtime-handshake/valid/
tests/staged-runtime-handshake/invalid/
```

Run:

```powershell
python tools/check_staged_runtime_handshake.py
python tools/check_staged_runtime_handshake.py --records <path-or-glob>
```

## Current Canaries

The invalid fixture set covers:

- missing required stage;
- stages out of order;
- route target not in burden floor;
- ACT target not in route targets;
- field_witness body_ref mismatch;
- NAR missing ACT burden;
- terminal state mismatch;
- release claims complete despite held/partial stage;
- B.5.4.1 sidecar claim without verifier evidence;
- arbitrary parser claim;
- runtime/default emission proof claim;
- package/provenance claim;
- guaranteed `T_lang` uptake claim;
- absolute or escaping path;
- malformed SHA256.

## Boundary

This contract is no-model scaffolding. It prepares a later staged harness but
does not itself prove runtime/default emission, broad proof-mode corpus
adoption, arbitrary full IR parsing, package/provenance, or guaranteed uptake.
