# v0.4.3.x Staged Runtime Handshake Contract

Status: `NO_MODEL_FIXTURE_CONTRACT; RETAINED_ARTIFACT_REPLAY_BRIDGE_LOCAL; STAGE_LOCAL_MODEL_SCOPE_SUPPORTED; STAGE_05_MRP_TERMINAL_CONTRACT_LIVE_CI_PASS; STAGE_06_FIELD_WITNESS_NAR_CONTRACT_LIVE_CI_PASS`.

This document defines the scratch-record contract for staged skill-as-code
execution. It is a harness/dev contract only. It does not run the runtime,
does not parse arbitrary prose into IR, does not claim model behavior, and
does not replace the full governed `output.md`.

2026-06-02 retained replay update: the contract now supports two no-model
surfaces:

- synthetic handshake fixtures for contract/canary proof;
- retained-artifact replay records that bind the stage handoffs to a real
  retained governed output plus retained verifier sidecars.

## Minimum Stage Sequence

```text
stage-01-intake
stage-02-layer-a-diagnostic-ir
stage-03-routing-owner-gate
stage-04-burden-execution-act
stage-05-mrp-reread-terminal-state
stage-06-field-witness-nar
stage-07-release-output
stage-08-verifier-sidecars
```

Every full staged record must appear exactly once and in order.

Stage-local model smoke records may use:

```json
{
  "mode": "staged-current-skill-stage-local-smoke",
  "stage_scope": {
    "stop_after_stage": "stage-03-routing-owner-gate",
    "stage_count": 3,
    "not_release_output": true,
    "not_verifier_sidecars": true
  }
}
```

That mode validates only the stage prefix through `stop_after_stage`. It is for
bounded current-skill diagnosis and cannot claim release output, sidecars, or
retained-corpus proof.

Stage-local model smoke records may stop after Stage 04 as well. A Stage 04
record proves only the bounded ACT/body-ref handoff prefix and cannot claim
MRP reread, field witness, release output, verifier sidecars, retained-corpus
promotion, package/provenance, or broad A/B/C/D closure.

Stage-local model smoke records may stop after Stage 05 as well. A Stage 05
record proves only the bounded MRP/reread/terminal-state handoff prefix and
cannot claim field witness/NAR emission, release output, verifier sidecars,
retained-corpus promotion, package/provenance, or broad A/B/C/D closure.

Stage-local model smoke records may stop after Stage 06 as well. A Stage 06
record proves only the bounded field_witness/NAR handoff prefix and cannot
claim release output, verifier sidecars, retained-corpus promotion, package/
provenance, or broad A/B/C/D closure.

## Required Handoffs

1. Intake -> Layer A

   - input digest / case id / source boundary is preserved;
   - no answer/release occurs yet.

2. Layer A -> Routing

   - burden floor exists;
   - selected or held N-frame exists;
   - live registers / diagnostic IR state exists;
   - unresolved or held state is explicit.

3. Routing -> Burden execution

   - owner/TTP route exists for each selected burden;
   - route is catalogue-backed or held with reason;
   - no owner activation occurs without eligibility.

4. Burden execution -> MRP

   - ACT rows exist;
   - body_ref exists;
   - ACT owner/operation/delta/Land fields are canonical or checker-normalizable;
   - Layer B body exists for each body_ref.

Stage 04 canonical handoff fields are:

```json
{
  "id": "stage-04-burden-execution-act",
  "status": "pass",
  "act_targets": ["B1"],
  "act_burdens": ["B1"],
  "act_body_refs": ["¹B₁", "¹B₂"],
  "act_rows": [
    "⟦ACT ¹B₁[source-status-repair.source-order] :: π=scientific-explanations-only-knowledge-source :: body_ref=¹B₁ :: Δ=Δ¹B:science-source-bounded :: Land(¹B)+⟧"
  ]
}
```

`act_targets`, `act_burdens`, `act_body_refs`, and `act_rows` are canonical
string lists. Optional `act_row_details` may carry richer per-row metadata, but
must agree with the canonical fields and must not replace `act_rows`. The
staged current-skill harness may normalize object-shaped `act_rows` only when
each object carries an explicit string `act_row`; objects without `act_row` are
invalid.

Stage 05 canonical handoff fields are:

```json
{
  "id": "stage-05-mrp-reread-terminal-state",
  "status": "pass",
  "terminal_states": {"B1": "landed"},
  "dependency_graph_edges": [],
  "no_new_resultant_proof": {
    "proved": true,
    "basis": "B1 landed and no generated burden remains live.",
    "unresolved_burdens": []
  },
  "reread_state": {
    "divergence_state": "settled",
    "curl_state": "resolved",
    "route_result_type": "no_new_resultant",
    "route": "STOP"
  }
}
```

`terminal_states` is a burden-id object and must include every Stage 04 ACT
burden. Optional `generated_burdens` must also be terminally accounted. Edges
may be strings such as `B1->B2` or objects with `from`/`to`, but every endpoint
must name a routed, activated, or generated burden. Stage 05 is not a release
surface and must not emit `release_output`, `field_witness`, `closure_claim`,
Grapher/certificate fields, or verifier sidecars.

Stage 06 canonical handoff fields are:

```json
{
  "id": "stage-06-field-witness-nar",
  "status": "pass",
  "field_witness_body_refs": ["¹B₁", "¹B₂"],
  "nar_burdens": ["B1"],
  "owner_activations": ["¹B₁", "¹B₂"],
  "normalized_activation_record": true,
  "register_deltas": {}
}
```

`field_witness_body_refs` must match Stage 04 `act_body_refs`. `nar_burdens`
must include Stage 04 ACT burdens and Stage 05 terminal-state burden keys.
`owner_activations` may be a body-ref string list, or an object list only when
every object has an explicit string `body_ref`; object-shaped evidence is
preserved as `owner_activation_details`. Model-scope Stage 06 records cannot
use only `normalized_activation_record: true`; they must provide structured
NAR evidence in `normalized_activation_record` or
`normalized_activation_record_details`. Stage 06 is not a release surface and
must not emit final output, Closing Formulation, Grapher, collapse-certificate,
proof-sidecar, or verifier-sidecar evidence.

5. MRP -> Field witness

   - dependency graph edges are explicit;
   - terminal states are explicit;
   - no-new-resultant or HOLD/PARTIAL is explicitly accounted.

6. Field witness -> Release

   - owner_activations mirror ACT rows;
   - normalized_activation_record mirrors field_witness/ACT;
   - field_witness convergence passes or release is HOLD/PARTIAL.

7. Release -> Verifier sidecars

   - output.md exists as the governed answer where release is claimed;
   - graph/certificate/Grapher sidecars exist where claimed;
   - optional B.5.4.1 full-IR projection sidecar is built only from validated
     evidence.

## Checker Contract

`tools/check_staged_runtime_handshake.py` validates:

- record root is a JSON object;
- schema is `staged-runtime-handshake-v1`;
- required stage order is present exactly once and in order;
- stage-local model records may validate a scoped prefix only when
  `stage_scope` is explicit;
- no stage is skipped;
- every handoff references existing stages;
- required handoff checks are present;
- non-claims are present and true;
- model-mode records carry `model_scope` and model-specific non-claims, while
  no-model records still require `not_model_smoke: true`;
- output paths, when referenced, are relative and do not escape the repo root;
- artifact SHA256 fields are well formed;
- retained replay artifact bindings, when present, point to real retained
  manifest case paths and repository-normalized hashes;
- pass handoffs preserve required stage fields;
- held/partial stages prevent downstream complete-closure claims.

The first semantic checks are intentionally bounded:

- `burden_floor` in stage 02 must match `route_targets` in stage 03;
- `route_targets` in stage 03 must be a burden-id string list;
- optional `route_target_details` in stage 03 must be a list of objects whose
  `burden_id` values appear in `route_targets`;
- `route_targets` in stage 03 must match `act_targets` in stage 04;
- `act_targets`, `act_burdens`, `act_body_refs`, and `act_rows` in stage 04
  must be non-empty string lists;
- every Stage 04 ACT row must start with `⟦ACT`, contain `body_ref=`, `Δ=`,
  and `Land(`, close with `⟧`, and expose a body ref listed in
  `act_body_refs`;
- every listed Stage 04 `act_body_refs` value must appear in at least one ACT
  row;
- optional Stage 04 `act_row_details` must agree with `act_targets` /
  `act_burdens`, `act_body_refs`, `act_rows`, and Stage 03 owner routes when
  owner IDs are present;
- detected Stage 04 ACT row owners must be backed by Stage 03 `owner_routes`;
- `terminal_states` in stage 05 must be a non-empty burden-id object;
- every Stage 04 ACT burden must appear in stage 05 `terminal_states`;
- stage 05 terminal-state values must use the controlled vocabulary `landed`,
  `held`, `held-with-reason`, `hold_partial`, `partial`, `carried-PARTIAL`, or
  `discharged-as-derivative`;
- every stage 05 generated burden must appear in `terminal_states`;
- stage 05 dependency graph edge endpoints must appear in the known
  routed/ACT/generated burden set;
- stage 05 `no_new_resultant_proof` must be boolean or structured object; a
  positive proof cannot coexist with unresolved burdens, and structured
  positive proofs require non-empty `basis`;
- stage 05 `reread_state`, when present, must use controlled
  divergence/curl/result/route tokens and cannot claim `STOP` while unresolved
  burdens remain;
- stage 05 must not emit release/final/verifier fields;
- `field_witness_body_refs` in stage 06 must be a non-empty string list and
  must exactly match Stage 04 `act_body_refs`;
- `nar_burdens` in stage 06 must be a non-empty string list and must include
  ACT burdens from stage 04 plus Stage 05 terminal-state burden keys;
- `owner_activations` in stage 06 must be a non-empty body-ref string list or
  an object list whose objects all have explicit string `body_ref` fields;
- optional Stage 06 `owner_activation_details` must have body refs contained
  in `field_witness_body_refs`; `burden_id`, when present, must appear in
  `nar_burdens`; `owner_id` and `operation`, when present, must be strings;
- Stage 06 `normalized_activation_record` is required. Boolean `true` is
  allowed for retained/no-model replay records, but model-scope records require
  structured NAR evidence in `normalized_activation_record` or
  `normalized_activation_record_details`;
- structured Stage 06 NAR evidence must include `n_frame`, `live_registers`,
  `burden_floor`, and `per_burden`; `burden_floor` must match Stage 02, and
  `per_burden` must cover `nar_burdens` and Stage 05 terminal burdens;
- `register_deltas` in stage 06 must be a parser-stable object or object list;
- stage 06 must not emit release/final/verifier fields;
- `terminal_states` in stage 05 must match `release_terminal_states` in stage 07;
- if stage 08 claims B.5.4.1 sidecar evidence, stage 07 must have output
  evidence and stages 05/06 must have terminal/NAR evidence.

If `stage-08-verifier-sidecars` claims B.5.4.1, it must reference:

- `tools/build_b5_full_ir_projection_sidecar.py`;
- sidecar schema `b5-retained-proof-mode-full-ir-sidecar-v1`;
- checker-owned final verifier role;
- non-claim that the sidecar does not prove fresh runtime/default emission.
- retained artifact bindings for the governed output, collapse certificate,
  warning-clean Grapher HTML, and B.5 full-IR projection sidecar.

The retained binding checker parses the bound retained output for
`field_witness`, visible ACT rows, and NAR evidence. The staged record's ACT
body refs and NAR burdens must agree with the retained output, and all bound
hashes must agree with the retained corpus manifest.

## Current Canaries

The invalid fixture set covers:

- missing required stage;
- stages out of order;
- route target not in burden floor;
- ACT target not in route targets;
- field_witness body_ref mismatch;
- NAR missing ACT burden;
- terminal state mismatch;
- release claims complete despite held/partial stage;
- B.5.4.1 sidecar claim without verifier evidence;
- arbitrary parser claim;
- runtime/default emission proof claim;
- package/provenance claim;
- guaranteed `T_lang` uptake claim;
- absolute or escaping path;
- malformed SHA256.
- retained replay case mismatch;
- retained output path/hash mismatch;
- missing retained B.5 sidecar binding under a B.5.4.1 claim;
- retained parsed ACT count mismatch;
- retained NAR burden mismatch;
- retained sidecar schema mismatch.
- object-shaped canonical `route_targets`;
- `route_target_details` pointing to an unknown burden;
- model-mode staged records without `model_scope`;
- model-mode staged records with `case_count` broader than one;
- model-mode broad-behavior claims;
- no-model records with `not_model_smoke: false`.
- canonical Stage 04 ACT/body-ref handoff shape;
- object-shaped Stage 04 `act_targets`;
- object-shaped Stage 04 `act_rows` without explicit `act_row`;
- Stage 04 ACT rows missing `body_ref=`;
- Stage 04 ACT rows missing `Land(`;
- Stage 04 body-ref mismatches;
- Stage 04 `act_row_details` mismatches;
- Stage 04 ACT owners not backed by Stage 03 `owner_routes`.
- missing Stage 05 `terminal_states`;
- Stage 05 `terminal_states` missing an ACT burden;
- unknown Stage 05 terminal-state token;
- Stage 05 dependency edge with an unknown endpoint;
- Stage 05 generated burden missing a terminal state;
- Stage 05 positive no-new-resultant proof with unresolved burdens;
- Stage 05 structured no-new-resultant proof missing `basis`;
- Stage 05 release/final field emission.
- missing Stage 06 `field_witness_body_refs`;
- Stage 06 field-witness body refs mismatching Stage 04;
- missing Stage 06 `nar_burdens`;
- Stage 06 `nar_burdens` missing an ACT burden;
- Stage 06 `nar_burdens` missing a terminal-state burden;
- Stage 06 owner activation object missing `body_ref`;
- Stage 06 owner activation body ref absent from field-witness refs;
- model-scope Stage 06 using only boolean NAR without structured details;
- structured Stage 06 NAR burden-floor mismatch;
- structured Stage 06 NAR missing a `per_burden` row for a NAR burden;
- malformed Stage 06 `register_deltas`;
- Stage 06 final/release/verifier field emission.

## Boundary

This contract is no-model scaffolding. It prepares a later staged harness but
does not itself prove runtime/default emission, broad proof-mode corpus
adoption, arbitrary full IR parsing, package/provenance, or guaranteed uptake.
The retained replay bridge proves only that one staged record can be bound to
one existing retained proof artifact set without mutating that retained output.
