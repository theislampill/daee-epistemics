## Decision Details

### 1. A.13.3 / Runtime-Default Hard-Register Emission

A.13.3 would change the runtime/default governed-output contract: outputs would
start emitting the versioned hard-register object rather than merely accepting
and checking it in focused fixtures. This matters because full register-state
NLA/isomorphism and B.5 IR decode need a stable, source-owned register object
from normal governed output or an explicitly defined projection source.

It should come before full IR decode implementation, or at least before any
claim that full IR decode operates over normal governed output. A preflight for
full IR decode can be written earlier, but the implementation should not assume
hard-register fields are normally emitted until A.13.3 is accepted.

Required owner/source families:

- `atomics/skill/references/diagnostics/diagnostic-ir.md`
- `atomics/skill/references/diagnostics/diagnostic-ir.schema.json`
- generated runtime via `tools/build_compiled_runtime.py` only if runtime text
  changes
- `tools/check_ir_instance_integrity.py`
- `tools/check_register_formalism_bridge.py`
- `tools/check_reproducibility.py`
- `tools/check_nla_decode_semantic_faithfulness.py` only after a decode input
  policy exists
- `tests/ir-fixtures/`
- `tests/register-formalism-bridge-fixtures/`
- retained-corpus sidecar checks only if governed outputs or retained fixtures
  are promoted

Stop conditions:

- schema-light retained artifacts fail without a version marker;
- A.13.3 would require weakening A.13.1/A.13.2 canaries;
- generated runtime must be hand-edited;
- output bloat or prose readability becomes a proof-scope regression;
- checker text starts claiming full IR decode or uptake.

Smallest safe first slice: docs-only A.13.3 decision-prep that names the
emission policy, exact source owners, compatibility canaries, and validation
commands. Implementation remains protected until owner acceptance.

### 2. Full IR Decode / B.5 Hard-Register Decode

A.13.1 and A.13.2 unblock part of the path: hard-register objects are now
version-gated and can be reconciled with field_witness/NAR evidence. What is
still missing is a stable source of hard-register state from normal governed
output or an explicitly accepted projection path, plus a decode definition that
distinguishes full IR-state reconstruction from current bounded ACT/body
semantic faithfulness.

Full IR decode should wait for the A.13.3 emission/projection decision. A
decision-prep or preflight can be written earlier, but implementation should
not proceed until the input source is explicit.

Smallest safe preflight:

- define input surfaces for full IR decode;
- define which fields are reconstructed versus merely checked;
- list negative canaries for decode overclaim;
- state that T_lang uptake remains unclaimed;
- preserve current schema-light B.5 evidence as bounded, not full decode.

### 3. Register-Composition / D.3 Fixture 62

A.13.2 changes the status of register-composition by giving the five hard
registers a reconciled checker/fixture path. It does not reopen fixture 62.
Fixture 62 is now closed as a D.3-adjacent no-model route/checker canary for
`unknown-pattern-typed` handling.

Future register-composition work should use fixture 63 or a new hard-register
composition fixture. It should remain A.13.3-adjacent unless it is purely a
schema-light D.3 concealment checker slice with no hard-register/runtime
emission implications.

Disposition: fixture 62 is accepted and closed; future composition work is
owner-gated and should be scoped as fixture 63/A.13-adjacent.

### 5. Broad Governed / Model Matrix

A broad governed/model matrix is any new campaign that asks the model/harness
to produce fresh governed outputs across multiple case families or a broad
case set, or that tries to prove default runtime behavior across a matrix
rather than through existing artifacts and no-model checker/fixture lanes.

Case families still possible include restoration-recoil variants, two-track
primary/restoration closure variants, divergence/curl/LoopBreak variants,
mixed-concealment variants, hard-output/Brandolini cases, and future
hard-register runtime outputs. They are not covered by no-model lanes because
static fixtures prove checker policy, not default governed generation breadth.

Open this only with explicit owner authorization naming case family, proof
level, budget/stop conditions, retained sidecars, expert prose/scope
requirements if hard-output cases are used, and release/non-release boundary.

### 6. Release / Provenance / Package

The v0.4.3.5 release/provenance lane is historical and complete for its source
boundary. A new release gate is appropriate only when a coherent new proof
bundle exists, such as accepted A.13.3 runtime emission with retained governed
evidence, full IR decode implementation with canaries, or a selected governed
matrix with retained proof corpus promotion.

Before another package/provenance lane:

- source boundary must be clean and pushed;
- live CI and Pages must pass;
- public docs truthfulness must be checked;
- package/provenance checks must be explicitly opened;
- release body/assets/download metadata must align with the exact package.

No current decision architecture work justifies v0.4.3.6 or v0.4.4.0 by
itself.

### 7. Future Group E / Maximal Trajectory

Group E remains future-only. E.1 noetic compiler semantics depends on
B.5/A.13/B.1. E.2 corpus diagnostic infrastructure depends on B.1/B.2/B.4 as
reusable data. E.3/E.4/E.5/E.7 depend on later taxonomy/corpus/decode work.
E.8 is horizon framing assembled from the future state of Groups A-D and E.1-E.7.

Do not promote Group E from horizon to implementation without explicit owner
selection of one row, one source family, and one proof level.
