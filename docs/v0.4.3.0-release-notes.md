# v0.4.3.0 Release Notes

v0.4.3.0 is a closure-reconstructibility and Mid-Reread Pressure release on the
`0.4.0.0` operative contract line. The public release is `v0.4.3.0`; do not use
an RC label for the public title or tag.

## Summary

v0.4.3.0 makes daee-epistemics more reconstructible and operational at
reread/closure time. It adds parseable closure-witness graph accounting,
machine-readable `field_witness`, local visualization/checking, and Mid-Reread
Pressure (MRP) as a behaviorally smoke-proven reread-time TTP.

Classification remains schema-light executable governance calculus. This is not
a full formal calculus, not a truth meter, and not a guaranteed-uptake claim.

## Encoding Hotfix

The published v0.4.3.0 package was refreshed after a whole-repo mojibake pass. A
double-encoding issue in the hard/full closure render contract had corrupted
parseable closure field names. The refreshed package preserves the canonical
forms `∇·B:`, `∇×κ:`, and `𝒞(Ψᴺ):`; package validation and
`tools/check_mojibake.py` now guard against recurrence.

## Behavioral Proof

v0.4.2.0 remains a strong governed baseline: it has a governed execution surface,
burdens, submoves, `Land(Bn)`, `R(H,Delta)`, and closure graph behavior. The
narrow difference is that v0.4.2.0 does not expose explicit MRP as a named
reread-pressure TTP, does not render MRP pressure slots, does not record
`MRP resultant`, and does not route through MRP before closure or next-burden
release.

Patched v0.4.3.0 repair14 produced operational MRP in the hard-compound
secularism/authority-order smoke:

- decisive local output: `tests/smokes/mrp-behavior/outputs/smoke6-hard-repair14-v0.4.3.0.md`;
- raw smoke output is local evidence and is not included as a release asset;
- MRP was judged substantive, not ornamental;
- node lineage was reconstructible:

```text
input -> burdens -> submoves -> Land(Bn) -> R(H,Delta)
-> MRP pressure activations -> MRP resultant -> graph/route
-> next burden/STOP -> closure/restoration
```

Execution mass is not proof by itself, but hard-compound output mass must be
plausible for the topology claimed. Repair14 passed the hard-compound topology
and mass gate.
